## B.1 估值引擎总览

```
                     ┌────────────────────────────────┐
入力                 │        EstimationEngine        │
fund_nav(前一日)  ──▶│  1. 路由：按 fund_type 选模型   │
fund_holding_report ─▶│  2. 权重估计（季报 ⊕ 回归）    │
实时行情(持仓股/指数)─▶│  3. 组合收益推算               │
fx / 时区差异     ──▶│  4. 校准层（偏差自学习）        │
                     │  5. 不确定度（σ → 置信区间）    │
                     └───────────────┬────────────────┘
                                     ▼
                        EstimateRun(navEst, pctEst, σ, method,
                                    contributions[], asOf, quality)
                                     │
                     收盘后 ▼        │ 净值公布后
                   写 estimation_run  ▼
                              estimation_accuracy（残差入库）
                                     ▼
                              estimation_calibration（更新参数）
```

**统一输出模型**

```kotlin
data class EstimateRun(
  val fundCode: String,
  val tradeDate: LocalDate,
  val asOf: Instant,
  val navPrev: BigDecimal,          // 前一日官方单位净值
  val navEst: BigDecimal,           // 估算净值
  val pctEst: BigDecimal,           // 估算涨跌幅 %
  val sigma: BigDecimal,            // 残差标准差（%）
  val method: Method,               // INDEX / HOLDINGS / REGRESSION / HYBRID / BOND / MMF / QDII / ETF
  val contributions: List<Contribution>,  // 归因明细
  val quality: Quality              // REALTIME / DELAYED / STALE
)
```

**五条实测红线（违反会显著劣化）**

1. ❌ **联接基金禁止用持股穿透**：实测股票占净比仅 2%~3%（90%+ 为持有目标 ETF），穿透等于只算 2% 仓位 → MAE 从 0.019% 恶化到 0.726%（**40 倍**）
2. ❌ **禁止用 ETF 二级市场交易价替代净值**：折溢价噪声使 001593 的 R² 从 99.97%（穿指数）掉到 **37.4%**（穿交易价）
3. ❌ **禁止对 QDII 无条件平移净值日期**：港股+A 股为主的 QDII 与 A 股**同日**（相关 0.96），平移 1 日会让相关性跌到 −0.08
4. ❌ **禁止无条件偏差校准**：残差均值≈0 时只引入噪声（见 §B.3 修正）
5. ❌ **禁止把季报权重当作主信息**：回归权重 γ=0.2 最优、γ=0.8 退化 → 季报已无回归未提取的增量信息

**❗ 不要上 CNN / LSTM / Transformer**（实证依据见 §B.11）

## B.2 模型明细

### B.2.1 INDEX：指数跟踪型

```
pct_est = Σ_j  w_j × r_index_j × (1 − te)  −  fee_daily
nav_est = nav_prev × (1 + pct_est/100)
```

- `w_j`：跟踪标的权重（多标的如「沪深300 + 中证500」按其合约权重）
- `te`：跟踪误差率（用近 60 日 `|r_fund − r_index|` 均值估计，默认 0.3~1.5%）
- `fee_daily ≈ (管理费 + 托管费) / 365`（指数基金通常合计 0.5%/年 → 约 0.0014%/日）

**精度**：指数基金通常 MAE < 0.12%。

### B.2.2 HYBRID：主动股混（核心，混合基金预测）

> ❖ **PCF 升级（第五轮实证，收益最大）**：主题因子的构建方式从「ETF 二级市场价格」
> 改为「**PCF 成分股权重合成指数**」——实测主题主动基金 **MAE 改善 31%、R² 67.4% → 93.6%**。
> 原因：ETF 二级市场价格含折溢价噪声（通信 ETF 价格波动比净值大 **80%**）。
> 生成方式见 `docs/02` §A.14；因子优先级：**PCF 合成指数 > ETF 价格 > 主题内个股**。
>
> ❖ **量化升级（第四轮实证）**：主动股票/混合品类改用 **Hedge 在线集成（Q6）**，
> 组合 6 个子模型（NNLS / 卡尔曼 / RLS / 弹性网 / Huber / 自适应窗口），
> 按指数损失动态加权 → 实测 MAE **0.3009% → 0.2198%（改善 27%）**，方向命中率 **93.5%**（最高）。
> 实现见 `tools/quant.py::OnlineEnsemble`。


```
pct_est = Σ_{i∈H} w_i^adj × r_i                 // 披露重仓部分
        + w_other × (β_other × r_bench)          // 未披露部分（"黑箱仓位"）
        + α_residual                             // 回归残差修正
        − fee_daily
```

**① 权重调整 `w_i^adj`**

季报只披露前十大重仓（合计可能仅 30%~80%），必须处理「其余仓位」：

```
w_disclosed = Σ_{i∈H} w_i                    // 披露合计权重
w_other     = max(0, stock_ratio − w_disclosed)   // stock_ratio 来自 assetAllocation
w_i^adj     = w_i × k ，k = min(1, stock_ratio / w_disclosed)   // 归一化到真实股票仓位
```

- `stock_ratio` 来自 `Data_assetAllocation`（季报口径），若缺失则用同类型基金中位数（股票型 88%、偏股混合 85%、灵活配置 70%、平衡 55%）。
- **滞后处理**：季报披露滞后最多 ~120 天。设 `age = today − report_date`，
  `decay = clamp(1 − age/240, 0.5, 1.0)`，权重向「行业指数」回退：
  `w_i^final = decay × w_i^adj + (1−decay) × w_i^sector`（`w_i^sector` 由回归法给出，见下）。

**② 回归权重（对"黑箱仓位"的量化）**

用近 N=60 个交易日的基金日收益 `y_t` 对候选标的收益矩阵 `X_t`（重仓股 + 行业/风格指数）做**带约束的岭回归**：

```
minimize   ‖y − X w‖² + λ‖w‖²
subject to w ≥ 0,  0 ≤ Σw ≤ 1
```

- 求解：坐标下降（N ≤ 40 维，单次求解 < 5 ms，可在手机上跑）
- `λ` 用时间衰减权重 `λ_t = 0.98^{N−t}` 增强近期数据权重
- 输出 `w_regression`，与季报权重做**凸组合**：

```
w_final = γ × w_report + (1 − γ) × w_regression,   γ = 0.6 默认
```

- 若回归与季报差异大（L1 距离 > 阈值）→ 判定为**风格漂移**，在 UI 提示「该基金近期持仓风格明显偏离季报披露」。

**③ 基准残差 `α_residual`**

- 用指数（沪深300/中证500/创业板指按回归权重）代表未披露仓位
- `α_residual` = 近 20 日 `(r_fund − r_portfolio_predicted)` 的 **EWMA 均值**（见校准层）

**④ 不确定性**

- 残差序列的标准差 `σ` → 置信区间 `pct_est ± 1.96σ`
- 披露越旧、`w_disclosed` 越小、基金换手越高 → `σ` 越大（乘上放大因子）

### B.2.3 BOND：债券型（❖ 已实测重写，详见 `docs/07` 第二部分）

> **实测要点**：债券基金日波动仅 1~20bp，因此「预测 0（或票息均值）」是**强基线**，
> 任何模型必须先证明能打败它。实测 7 种算法交叉验证结论如下。

**主模型（B5）：债券 ETF + 国债期货 非负岭回归**

> ❖ **量化升级（2026-10-15 第四轮实证）**：债券品类改用 **非负弹性网（L1+L2，坐标下降）**
> 而非纯岭回归 —— 实测 MAE **8.14bp → 5.17bp（改善 37%）**。
> 原因：债券信噪比极低（σ 仅 1~20bp），L1 稀疏选择能剔除大量无信息因子。
> 实现见 `tools/quant.py::ElasticNetNN`（纯 numpy，可移植 Kotlin）；对比见 `docs/07` 第四部分。


```
pct_est = Σ_i w_i × r_etf_i  +  Σ_j v_j × r_future_j
    r_etf    ：13 只债券 ETF（短融/国债5年/活跃国债/十年国债/30年国债/政金债/
               公司债/城投债/可转债/地方债 等，覆盖不同久期与品种）
    r_future ：TS0(2年) / TF0(5年) / T0(10年) / TL0(30年) 国债期货
    求解     ：NNLS(λ=0.5, top-K=6, 时间衰减 0.97)   ← 见 §B.11
```

**实测精度（429 交易日，单位 bp=0.01%）**

| 算法 | 平均 MAE | R² | 显著日方向命中 |
|---|---|---|---|
| 零基线（预测 0/均值） | 9.49bp | 0% | — |
| 单 ETF 因子 + OLS | 4.45bp | 48.8% | **90.8%** |
| 多 ETF NNLS | 4.50bp | 60.2% | 85.9% |
| 仅国债期货 | 8.14bp | 48.9% | 80.2% |
| **B5 ETF + 期货** | **4.30bp** | **64.5%** | 87.3% |
| 久期理论（−D×Δy） | 10.09bp | 41.1% | 79.2% |

**按子类型路由（关键）**

| 子类型 | 最优方法 | 实测 |
|---|---|---|
| 中长期纯债 | B5 模型 | 7.04bp → **4.24bp**（改善 40%） |
| 债券指数 | B5 模型 | 3.18bp → **2.02bp**（36%） |
| **短债 / 中短债** | **零基线（不做估算）** | 0.64bp vs 模型 0.87bp → **模型反而差 36%** |
| 二级债基（含权） | B5 + 股票因子 | 40.45bp → **20.80bp**（49%） |
| 可转债基金 | ⚠️ 因子集不足 | 72.94bp → 70.18bp（仅 4%，待补） |
| 货币型 | 见 §B.2.4 万份收益模型 | 误差 < 0.005% |

> ❌ **短债基金禁止做盘中估算**：日波动 0.6~1.0bp，票息累积占主导，
> 模型噪声（0.74~1.04bp）大于信号 → UI 显示「基本不变」比给一个假数字更诚实。

**盘中刷新节奏（实测收敛曲线：10:30 → 15:00 误差单调下降）**

| 时段 | 刷新频率 | 相对零基线改善 | UI 策略 |
|---|---|---|---|
| 09:30–11:30 | 30 min | −0% ~ 12% | 标注「参考意义有限」 |
| 13:00–14:00 | 15 min | 18% ~ 25% | 显示置信区间 |
| **14:00–15:00** | **5 min** | **25% ~ 29%** | **主推（决策窗口）** |
| 15:00–15:15 | 定格 | 29% | 国债期货晚于 A 股收盘（15:15） |
| 15:15 之后 | 停止 | — | 显示「待官方净值」（中债估值约 17:00–19:00） |

**短债的 AR 修正**：短债基金残差 ACF(1)=+0.15~+0.32（净值平滑特征），
加 AR(1) 残差修正后 MAE 再降 21%~25%（中长期纯债与转债 ACF≈0，无效）。

### B.2.3c 不建模品类（诚实原则）

| 品类 | 日波动 σ | 零基线 MAE | 模型 MAE | 结论 |
|---|---|---|---|---|
| 短债 / 中短债 | 0.6~1.0bp | **0.64bp** | 0.87bp | 不建模 |
| 同业存单 | 0.88bp | **0.68bp** | 0.72bp | 不建模 |

**理由**：这两类基金净值由**票息累积**主导（几乎匀速增长），日内利率波动带来的噪声
小于模型引入的误差。**UI 应显示「基本不变 / 今日预计 +x.xx bp（按票息）」而非给一个假估算值。**

### B.2.4 MMF：货币基金

```
r_daily = 万份收益 / 10000
pct_est = 昨日万份收益 与 近7日万份收益均值 的加权
```

- 货币基金收益几乎无波动 → 直接用「近 7 日万份收益均值」作为估算，误差 < 0.005%
- 7 日年化 = `(Π(1+r_i))^{365/7} − 1`

### B.2.5 QDII：跨市场时差

```
pct_est = Σ_c w_c × r_c(t_c) × fx_factor_c  − fee_daily
```

| 情形 | 处理 |
|---|---|
| 持仓为港股 | 用港股实时（同时段） |
| 持仓为美股，A 股时段 | 用**纳指期货/上一交易日美股收盘** + 当日汇率变动，标注 quality=DELAYED |
| 美股盘中（北京深夜） | 用实时美股 + 实时汇率，pct 持续刷新（此时 A 股已收盘，基金净值按次日归属） |
| 净值归属 | QDII 净值通常 T+1/T+2 公布，需 `trade_date` 与 `nav_date` 分离 |

- 汇率：`fx_factor = (1 + ΔUSDCNY/USDCNY)`（对美元资产）
- **必须 UI 标注**：「美股尚未开盘，此为预估，误差可能大于 1%」

### B.2.6 ETF：场内基金

```
nav_est ≈ price / (1 + premium_prev)      // premium_prev = 前一日溢价率
pct_est = (price − prev_close) / prev_close
```

- 场内 ETF 直接用实时价格，反而比估算更准；净值估算主要用于「IOPV 缺失时」与「份额折算校验」。

## B.3 校准层（偏差自学习）

> ⚠️ **实测修正**：下文的**无条件** EWMA 校准在真实数据上反而使 MAE 变差（0.641% → 0.651%），
> 因为残差均值本就接近 0（0.016%），无条件修正只引入噪声。
> **生产实现必须加统计显著性门槛**：`|bias| > z·σ/√n`（z=2, n≥20）才启用，否则不修。
> 参考实现：`tools/engine.py::SignificantBiasCalibrator`。

净值公布后，用真实值反哺模型——**这是估值能否长期可用的关键**。

```
残差      e_t = pct_actual − pct_est
EWMA偏差  b_t = θ·e_t + (1−θ)·b_{t−1}        θ = 0.25（自适应：e 突增时 θ→0.5）
标准差    σ_t = sqrt(EWMA((e − b)²))
修正输出  pct_final = pct_est + b_t
区间      pct_final ± z·σ_t                   z = 1.96（95%）
```

**漂移检测**（触发模型重估）

| 条件 | 动作 |
|---|---|
| 连续 5 日 `sign(e_t)` 相同且 `\|b_t\| > 0.3%` | 重跑回归权重（`w_regression` 刷新） |
| 近 20 日 `σ_t > 1.0%` | 降低 `γ`（更信回归），并在 UI 提示「估值可靠性下降」 |
| 季报更新 / 基金公告换经理 | 全量重估并重置 `b_t` |
| 单日 `\|e_t\| > 3σ` | 标记为「异常日」，不纳入 EWMA（避免污染） |

**精度面板呈现**


## B.5 银行金价模型（浙商银行）

**核心公式**

```
银行买入价(客户买入黄金) ≈ P_ref × (1 + s_buy)
银行卖出价(客户卖出黄金) ≈ P_ref × (1 − s_sell)
P_ref = AU9999（上金所）或 折人民币伦敦金
点差   = 买入价 − 卖出价
```

- `s_buy`、`s_sell`：由历史样本（OCR / 抓包 / 手动录入）拟合；初始值取行业常见区间（0.3%~1%）
- **校准**：每次获得真实报价，用 `s = price / P_ref − 1` 更新点差估计（EWMA，θ=0.3）
- **估值口径**：持仓市值一律用**卖出价**（可变现），并在 UI 明示
- **费用**：`bank_gold_product` 记录 `redeem_fee`（赎回费，常按持有天数分档）、`withdraw_fee`（提金费，元/克）、`min_gram`（最小积存单位）

```
净可变现价值 = grams × 卖出价 − 赎回费（若有）− 提金费（若提取实物）
克成本       = 累计投入(含费) / 累计克数
```

**点差漂移监控**：每日记录 `点差 / P_ref`，若 30 日 EWMA 偏离拟合值 > 30%，提示用户重新校准。

## B.7 收益计算算法（伪代码）

### B.7.1 移动加权平均成本

```kotlin
fun applyBuy(pos: Position, shares: BigDecimal, nav: BigDecimal, fee: BigDecimal) {
  pos.totalShares += shares
  pos.totalCost   += shares * nav + fee         // 成本含费
  pos.avgCost      = pos.totalCost / pos.totalShares
}
fun applySell(pos: Position, shares: BigDecimal, nav: BigDecimal, fee: BigDecimal) {
  val costOut = pos.avgCost * shares            // 卖出不改变 avgCost
  pos.realizedProfit += shares * nav - fee - costOut
  pos.totalShares    -= shares
  pos.totalCost      -= costOut                 // 剩余成本同步减少
}
```

### B.7.2 XIRR（资金加权，Newton + 二分兜底）

```kotlin
fun xirr(cf: List<CashFlow>): Double {
  val t0 = cf.first().date
  fun npv(r: Double) = cf.sum { it.amount / (1 + r).pow(days(t0, it.date) / 365.0) }
  var r = 0.1
  repeat(100) {
    val f = npv(r)
    val d = (npv(r + 1e-6) - f) / 1e-6
    val next = r - f / d
    if (abs(next - r) < 1e-9) return next
    r = next.coerceIn(-0.9999, 100.0)
  }
  // 兜底：二分法在 [-0.9999, 10] 搜索 npv 变号区间
}
```

现金流构造：买入 = 负现金流，卖出/分红 = 正现金流，期末市值 = 正现金流。

### B.7.3 TWR（按现金流切分）

```
每个现金流发生的日期间隔为一个子区间：
  子区间收益 r_i = (期末市值 − 期间净流入) / 期初市值 − 1
TWR = Π(1 + r_i) − 1
年化 = (1 + TWR)^(365/总天数) − 1
```

**产品化的解释力（关键）**
- `TWR` 高、`XIRR` 低 → "基金选得不错，但我的加仓时点拖累了收益"
- `TWR` 低、`XIRR` 高 → "运气/择时好，但标的本身一般"
- 在简报里用一句话把这个差异讲清楚 → 这是同类产品几乎不做的差异化。

## B.10 提醒规则引擎（去抖 / 升级触发 / 配额）

> 本节 DDL 是 B.8 的补充（`alert_rule` / `alert_state` / `live_activity` 以本节为准）。

### B.10.1 触发判定

```kotlin
enum class Decision { WAIT, FIRE, ESCALATE, SUPPRESS }

fun evaluate(ctx: RuleContext): Decision {
    val r = ctx.rule

    // ⓪ 时段门控（金价夜盘规则 allowOffHours=true 时跳过）
    if (!r.allowOffHours && ctx.marketStatus !in OPEN_STATES) return Decision.WAIT
    if (inQuietHours(ctx.now, r.quietHours) && !r.allowOffHours) return Decision.WAIT

    // ① 幅度：方向 + 阈值
    val breach = when (r.direction) {
        ABOVE -> ctx.est >= r.threshold
        BELOW -> ctx.est <= r.threshold
        CROSS -> ctx.crossed(r.threshold)      // 上穿/下穿（关口价）
    }
    if (!breach) return resetStreak(ctx)       // 关键：不满足即清零，避免"断续 N 次"被误判为连续

    // ② 显著性：超出量必须大于估值噪声 σ
    val excess = when (r.direction) {
        ABOVE -> ctx.est - r.threshold
        BELOW -> r.threshold - ctx.est
        CROSS -> ctx.est - r.threshold
    }.abs()
    if (excess < r.sigmaMultiplier * ctx.sigma) return Decision.WAIT

    // ③ 持续性：连续 N 次采样均满足 ① + ②
    if (ctx.state.streak + 1 < r.minStreak) return Decision.WAIT

    // ④ 冷却（含升级触发）
    if (ctx.now < ctx.state.cooldownUntil) {
        val level = escalationLevel(ctx)       // floor(|excess| / threshold)
        val canEscalate = level > ctx.state.escalationLevel &&
                          ctx.state.fireCountToday < r.dailyCap
        return if (canEscalate) Decision.ESCALATE else Decision.SUPPRESS
    }

    // ⑤ 配额
    if (ctx.state.fireCountToday >= r.dailyCap) return Decision.SUPPRESS
    if (globalFiredToday() >= GLOBAL_DAILY_CAP) return Decision.SUPPRESS

    return Decision.FIRE
}
```

**四条不变式（单测必覆盖）**

| 不变式 | 含义 |
|---|---|
| 幂等 | 同一次采样重复评估不改变状态（用 `last_eval_at` 去重） |
| 单调清零 | `breach == false` 时 `streak = 0` |
| 跨日按**交易日**重置 | 上金所夜盘跨自然日，按交易归归属 |
| σ = 0 安全 | σ 为 0/缺失时用默认下限（如 0.05%），绝不除零或无限触发 |

### B.10.2 状态机

```
        ┌────────── 不满足 ①②（streak 清零）──────────┐
        ▼                                              │
   [IDLE] ──满足①②──▶ [PENDING(streak=n)] ──streak ≥ minStreak──▶ FIRE
        ▲                     │                                    │
        │                     └── breach=false ──▶ [IDLE]          ▼
        │                                                    [COOLDOWN]
        │                       升级：[COOLDOWN] ──突破 2× 阈值──▶ FIRE(escalate)
        └──────────────────── 冷却到期 ────────────────────────────┘
```

`FIRE` 动作 = 写 `alert_log` + 发通知（受频道配额） + 必要时创建/更新 `live_activity`。

### B.10.3 采样频率与零额外流量

| 标的 | 评估频率 | 数据来源 |
|---|---|---|
| 基金估算涨跌 / 净值关口 | 60 s | 复用估值引擎输出，**不新增请求** |
| 持仓 / 组合预估盈亏 | 60 s | 持仓 × 估算派生（纯本地计算） |
| 金价（AU9999 / 伦敦金折人民币） | 60 s（对应市场时段） | 复用上金所/腾讯行情管道 |
| 浙商银行金价 | 用户主动刷新 / 每日 1 次 | OCR / 手动 / 点差模型 |

> **核心设计**：提醒引擎是估值/行情管道的**订阅者**，不是独立轮询者。零额外网络请求 → 零额外限流与风控风险。

### B.10.4 上线前噪声回放（必做）

用过去 60 个交易日的真实历史数据（净值 + 分时）离线回放规则判定：

```
目标：
  正确触发率 ≥ 80%（相对"当日实际收盘确实超阈值"的样本）
  误报率   ≤ 10%（报了但收盘实际未超阈值）
  单只基金日均通知 ≤ 1 条

参数寻优网格：
  minStreak        ∈ {1, 2, 3, 5}
  sigmaMultiplier  ∈ {0, 0.5, 1.0, 1.5}
  cooldown         ∈ {15, 30, 60} min
```

寻优结果写入默认值表，并在设置页暴露为"提醒敏感度"三档（保守 / 标准 / 灵敏）。

## B.11 实证结论（为什么不上 CNN / LSTM）

> 完整实验见 `docs/07-估值引擎实证报告.md`；参考实现见 `tools/engine.py`、`tools/benchmark.py`

### B.11.1 三项诊断：残差里已经没有可用信息

**诊断 1 · 残差自相关 ≈ 0（白噪声）**

| 基金 | ACF(1) | ACF(2) | ACF(3) | ACF(4) | ACF(5) |
|---|---|---|---|---|---|
| 005729 南方AI | +0.10 | +0.03 | −0.08 | −0.09 | −0.13 |
| 006281 万家AI | +0.20 | +0.01 | −0.05 | −0.06 | −0.06 |
| 005962 宝盈AI | −0.00 | +0.02 | −0.12 | −0.01 | −0.11 |
| 002190 农银新能源 | −0.02 | −0.09 | +0.00 | −0.08 | −0.01 |
| 110022 易方达消费 | +0.10 | −0.01 | −0.08 | −0.05 | −0.02 |

→ 无可学习的时序结构，序列模型**没有学习目标**。

**诊断 2 · 残差与全部可观测特征相关性 < 0.1**

残留相关性最高的是 110022 与沪深300（−0.21），其余全部接近 0。
→ 没有系统性偏差可修正，**加特征也没用**。

**诊断 3 · 样本量不足**

每只基金 429 个交易日，可用特征 15~41 维。深度网络参数量远超样本量 → **必然过拟合**。

### B.11.2 提升全部来自信息，不来自模型

| 手段 | 平均 MAE | 相对基线 |
|---|---|---|
| 季报穿透（基线） | 0.505% | — |
| + 换成回归权重 | 0.205% | −59% |
| + 因子池扩展到**全历史持仓**（15~41 只） | 0.399% | −21%（在主题基金子集上） |
| + 指数直连（适用基金） | **0.026%** | **−97%** |
| **路由后综合**（13 只样本） | **0.272%** | **−70%**（vs 基准指数法 0.910%） |
| 扩样至 32 只后 | **0.308%** | — |

### B.11.3 先进算法的正确落点

| 场景 | 该用 | 不该用 |
|---|---|---|
| 权重缓慢漂移追踪 | ✅ **RLS / Kalman**（遗忘因子递推最小二乘） | ❌ 端到端深度网络 |
| 高维因子选择 | ✅ **NNLS / L1 稀疏回归**（`scipy.lsq_linear`，已用于生产参考实现） | ❌ 暴力全因子回归 |
| 偏差修正 | ✅ **t 检验门槛**（显著性才修） | ❌ 无条件 EWMA |
| 多基金截面预测 | ⚠️ 可探索（样本可跨基金池化，样本量 ×N） | — |

### B.11.4 后续提升路线（按性价比）

| # | 手段 | 预期 | 可行性 |
|---|---|---|---|
| 1 | **ETF 申赎清单（PCF）**：交易所每日公布 ETF 成分与权重 → 联接基金持仓滞后从 **90 天缩到 1 天** | 极大 | 高（公开数据） |
| 2 | 半年报/年报**全量持仓**（非仅前十大） | 大 | 高 |
| 3 | 同经理 / 同公司同类基金持仓作先验 | 中 | 高 |
| 4 | 东财 496 个行业/概念板块指数作候选因子（当前仅 13 个手工主题 ETF） | 中 | 中 |
| 5 | ETF 折溢价与资金流向因子 | 小 | 中 |

> **PCF 是唯一能结构性改变精度的数据源**，优先级最高。

## B.12 估算分级与降级链（P0，产品正确性核心）

> **审计发现**：若对短债/同业存单也报"估算涨跌幅"，模型误差（0.87bp）大于信号（0.64bp）
> —— 那个数字是**负价值**，且构成误导。必须建立分级体系。

### B.12.1 估算分级

```kotlin
enum class EstimateGrade {
    EXACT,        // 场内实时价格，非估算
    HIGH,         // R² ≥ 95% 且 MAE ≤ 0.1%
    MEDIUM,       // R² 85~95% 或 MAE ≤ 0.6%
    LOW,          // R² < 85%（科技/主题主动基金）
    NONE,         // 不建模品类（短债/同业存单）→ 禁止显示数字
    UNAVAILABLE,  // 数据源不可用 / 新基金 < 20 交易日
}
```

### B.12.2 自动路由规则

```
1. 场内标的（有实时价格）                      → EXACT
2. 指数 / ETF联接 / 黄金联接（T0 命中）         → HIGH
3. 主动股票 / 混合（T1）                        → 按 20 日滚动 R² 动态定 HIGH/MEDIUM
4. 科技 / 主题主动（T1，实测 R² 71~87%）         → MEDIUM / LOW
5. 债券（B5，改善 ≥ 30%）                       → MEDIUM
6. 短债 / 中短债 / 同业存单（判定"不建模"）      → NONE
7. 源失败 / 无持仓数据 / 新基金                  → UNAVAILABLE
```

**滚动 R² 判定**（每 20 日复核一次，用近 20 日样本外残差）

```
R²_rolling = 1 − MSE_model / MSE_baseline
   ≥ 0.95 → HIGH
   0.85~0.95 → MEDIUM
   < 0.85 → LOW
   若 R²_rolling < 0（模型不如零基线）持续 10 日 → 自动降级为 NONE
```

> **自动降级是关键**：品类判定靠静态规则，但**精度靠滚动实测**。
> 若某基金连续跑输零基线，系统必须自己认输并停止给数字。

### B.12.3 降级链（每一级都要有 UI 表现）

```
T0 指数直连
  ↓ 跟踪指数未知 / 回归失败
T1 扩展池回归
  ↓ 持仓池不可用 / 数据不足
T2 季报穿透
  ↓ 季报未披露（新基金）
零基线（票息/均值）
  ↓ 该品类已判定不适合建模
NONE（不显示数字，显示状态文案）
```

### B.12.4 展示矩阵

| 等级 | 主数值 | 角标 | 副文案 |
|---|---|---|---|
| EXACT | 实时价 + 涨跌 | 无 | 「场内实时价 · 溢价 +0.12%」 |
| HIGH | 估算涨跌（实色） | 弱「估算」 | 「估值 ±0.07% · 14:32」 |
| MEDIUM | 估算涨跌 | 「估算」+ 置信区间 | 「区间 +0.98%~1.32% · 误差 0.21%」 |
| LOW | 估算涨跌（半透明） | 「估算 · 参考意义有限」 | 「近 20 日误差 0.54% · 本类基金波动大」 |
| **NONE** | **不显示数字** | **无** | 「**短债波动极小，不提供盘中估算**」+ 当日票息估算 |
| UNAVAILABLE | `—` | 「暂无」 | 「数据源不可用 · 显示 10-14 净值」 |

### B.12.5 不建模品类的替代信息（不能什么都不给）

对短债/同业存单，用**票息累积**给一个诚实的数字：

```
预计当日收益 ≈ 近 7 日日均收益（bp）
UI: 「今日预计 +0.02bp（按近 7 日票息）· 短债不做盘中估算」
```

这比"预测 0"更诚实也更有信息量，且**不会误导为市场预测**。
