## D.2 解析器设计

### D.2.1 解析器契约

```kotlin
interface Parser<IN, OUT> {
    val name: String
    val sourceReliability: Reliability   // HIGH / MEDIUM / FRAGILE
    fun parse(input: IN): Result<OUT>    // 失败必须给出原因，不得抛异常
}

// 统一容错工具
object NumOrNull {
    private val BLANKS = setOf("", "-", "--", "null", "N/A", "—", "0.00")
    fun parse(s: String?): Double? = s?.trim()?.takeIf { it !in BLANKS }?.toDoubleOrNull()
}
```

**三级容错原则**
1. **数值级**：空/`--`/`null` → `null`（UI 显示 `—`），绝不转成 0
2. **记录级**：单条记录解析失败 → 丢弃该条 + 计数，不整体失败
3. **响应级**：结构变化（关键字段全缺）→ 判定"格式变更"，抛 `ParserSchemaChanged` → 触发诊断包 + 降级

### D.2.3 P2 详细设计（`pingzhongdata` JS 解析）

```kotlin
// 输入：615 KB 的 JS 文本；输出：结构化画像
// 策略：白名单变量 + 正则定位 + 分段 JSON.parse（不引入 JS 引擎，避免体积与安全面）
private val VAR_RE = Regex("""var\s+(\w+)\s*=\s*""")

fun parse(js: String): FundProfile {
    val vars = extractByWhitelist(js, WHITELIST)   // 只取需要的变量，避免解析 600KB
    return FundProfile(
        name  = vars.string("fS_name"),
        code  = vars.string("fS_code"),
        navTrend = vars.jsonList("Data_netWorthTrend")   // [{x: ts, y: nav, equityReturn, unitMoney}]
            ?.mapNotNull { it.toNavPoint() }.orEmpty(),
        assetAlloc = vars.jsonList("Data_assetAllocation")
            ?.let { parseAllocation(it) }.orEmpty(),
        managers = vars.jsonList("Data_currentFundManager"),
        scale = vars.jsonList("Data_fluctuationScale"),
        returns = listOfNotNull(
            vars.double("syl_1n")?.let { PeriodReturn(YEAR_1, it) },
            vars.double("syl_6y")?.let { PeriodReturn(MONTH_6, it) },
            vars.double("syl_3y")?.let { PeriodReturn(MONTH_3, it) },
            vars.double("syl_1y")?.let { PeriodReturn(MONTH_1, it) },
        ),
        rateNow = vars.double("fund_Rate"),
        rateSource = vars.double("fund_sourceRate"),
    )
}

// 白名单示例
val WHITELIST = setOf(
    "fS_name","fS_code","fund_Rate","fund_sourceRate","fund_minsg",
    "Data_netWorthTrend","Data_ACWorthTrend","Data_assetAllocation",
    "Data_fundSharesPositions","Data_fluctuationScale","Data_currentFundManager",
    "Data_grandTotal","Data_performanceEvaluation","syl_1n","syl_6y","syl_3y","syl_1y"
)
```

**关键取舍**：不跑 JS 引擎（QuickJS/Rhino）——省 ≥2 MB 体积、无沙箱风险、更快。代价是变量结构变化时要改解析器（由 P2 契约测试兜底）。

### D.2.4 P3 详细设计（十大重仓 HTML）

```kotlin
// FundArchivesDatas.aspx 返回 var apidata={ content:"<div class='box'>..." }
// 三重锚点，任一命中即可
private val CONTENT_SELECTORS = listOf(
    "div.box:has(h4.t)",        // 新版
    "table.w782",               // 旧版
    "div#cctable"               // 兜底
)

fun parse(raw: String): List<HoldingRow> {
    val html = extractJsString(raw, "content") ?: return emptyList()
    val doc = Jsoup.parse(html)
    val period = Regex("""(\d{4})年(\d)季度""").find(doc.text())
        ?.let { "${it.groupValues[1]}Q${it.groupValues[2]}" } ?: return emptyList()  // 无报告期 → 不可信，丢弃
    val disclose = doc.selectFirst("label.right.lab2, .lab2")
        ?.text()?.let { DateGuess.from(it) }          // 披露日：防未来函数的关键
    return CONTENT_SELECTORS.firstNotNullOfOrNull { sel ->
        doc.select(sel).firstOrNull()?.let { parseTable(it, period, disclose) }
    }.orEmpty()
}
```

**必须落库 `disclose_date`**：估值回测用报告期末会引入未来函数（03 §B.4 已列为纪律）。若页面无披露日，则取 `报告期末 + 90 天` 作为保守估计并标 `disclose_date_estimated = true`。

## D.4 回填（Backfill）设计

| 场景 | 数据 | 分页 | 估计量 | 耗时（限速 2 req/s） |
|---|---|---|---|---|
| 首次安装 · 基金净值 | `f10/lsjz` | 每页 50 条 | 20 年 ≈ 5000 行 / 只 | 约 2 s/只 |
| 深度历史（回测用） | 同上传全量 | — | 同 | — |
| ETF/指数 K 线 | `kline` `lmt=dktotal` | 单请求可拿全量 | 8742 条（上证日线） | 1 请求 |
| 上金所日线 | `Dailyhq` | 单请求 10 年 | ~2400 条 | 1 请求 |
| 季报重仓历史 | `jjcc` 按年份 | 每年 1 次 | 5 年 = 5 请求 | 5 请求 |
| 板块全量 | `clist` | 每页 100 | 496 个 | 5 请求 |

**执行规则**
1. **优先级队列**：持仓中的标的 > 自选 > 其他；基金净值优先于 K 线
2. **断点续传**：`sync_log`/进度表记录 `(task, key, cursor)`，中断后续跑
3. **限速**：与实时任务**共享令牌桶**，回填使用"空闲令牌"（实时任务优先）
4. **UI**：`设置 → 数据健康 → 深度回填`，显示进度与预估剩余时间，可暂停/取消
5. **仅在 WiFi + 充电时自动执行**（大任务）；用户可强制立即执行
6. 回填期间的实时数据请求优先级最高，回填任务可被抢占

## D.5 OCR 解析器（持仓截图 & 银行金价）

### D.5.1 模板 Schema

```yaml
# templates/alipay_holdings.yaml
id: alipay_holdings
app: 支付宝
version: 2026.10
match:                       # 页面识别：命中 ≥2 个锚点才认为匹配
  anchors: ["持有", "金额", "昨日收益", "总金额"]
  negative: ["基金排行", "买入"]
fields:
  - name: fund_name
    type: text
    match: { anchorLeft: "名称", orIndex: 0 }
  - name: fund_code
    type: code6              # 6 位数字正则 \b\d{6}\b
  - name: shares
    type: number
    match: { anchorRight: "份额", unitRegex: "(份|股)" }
  - name: amount
    type: money
    match: { anchorLeft: "金额", unitRegex: "¥|元" }
  - name: profit
    type: money
    match: { anchorRight: "收益" }
rowStrategy:                 # 如何把文本块聚类成"行"
  type: yCluster
  tolerance: 14              # px，按屏幕密度归一化
```

### D.5.2 解析算法

```
ML Kit 输出: List<TextBlock>(text, boundingBox)
  ↓ ① 归一化：按屏幕宽度归一化坐标（不同分辨率/字号可比）
  ↓ ② 行聚类：按 boundingBox.centerY 以 tolerance 聚类（容忍轻微错位）
  ↓ ③ 模板匹配：命中锚点 → 按 anchorLeft/anchorRight 在行内切片取数
  ↓ ④ 类型解析：code6 / money / number（处理千分位、"份"、"+"、"-"）
  ↓ ⑤ 一致性校验（关键）：
       |shares × nav − amount| / amount ≤ 2%   （若能识别到净值）
       holding.profit ≈ amount − cost           （若能识别到成本）
       同一列表内 code 不重复
  ↓ ⑥ 置信度：
       score = w1·锚点命中率 + w2·必填字段完整率 + w3·一致性通过率
       score < 0.75 → 标记"低置信度"，UI 强制人工核对（默认不勾选）
  ↓ ⑦ 输出候选行 → 用户确认页（C.3.4）
```

**设计红线**：OCR 结果**永不直接写库**，必须经用户确认页；每次导入生成 `import_batch` 可整批撤销。

### D.5.3 模板迭代流程

```
用户反馈"识别不准" → 一键附带：原始截图（可选）+ ML Kit 文本块 JSON（脱敏后）
  → 本地导出为 `ocr_feedback.zip`
  → 开发者本地用同一 ML Kit 版本复现 → 修模板 → 加 fixture → CI 通过 → 发版
```
模板以**资源文件**形式随 App 发布，不依赖服务端（符合本地优先）；模板版本号随 App 版本，便于问题定位。

## D.6 CSV / Excel 导入器

### D.6.1 预处理

| 步骤 | 规则 |
|---|---|
| 编码探测 | BOM → UTF-8；无 BOM → 尝试 GBK（中文账单常见），用"解码后中文占比"启发式判定 |
| 分隔符探测 | 统计 `,` `\t` `;` 出现次数方差 → 选最稳定者 |
| 表头定位 | 跳过前导说明行（"以下为您的交易记录"）：从第一个含 ≥3 个已知列名的行开始 |
| 金额清洗 | 去 `¥`/`,`/空格；`(123)` 视为负数；全角转半角 |
| 日期解析 | 支持 `2026-10-15` / `2026/10/15` / `20261015` / `2026年10月15日` |

### D.6.2 来源字段映射

| 来源 | 关键列 | 映射 |
|---|---|---|
| 支付宝（账单/基金导出） | 交易时间、交易类型、金额、商品说明、交易状态 | 时间→`trade_date`；类型→`txn_type`（买入/卖出/分红）；金额取绝对值 + 方向；商品说明→基金名（**需映射到代码**） |
| 天天基金（持仓导出） | 基金代码/名称、持有份额、持有金额、成本价、持有收益 | 生成"期初持仓"`TRANSFER_IN` 流水（份额 + 成本从 0 建立） |
| 券商（对账单） | 成交日期、证券代码、买卖方向、成交价格、成交数量、手续费 | 直接映射；注意 A 股 100 股整手、场内 ETF 费用 |
| 通用模板 | 用户自定义列映射 | 提供"列映射向导"（拖拽） |

**基金名 → 代码**：优先本地 `fund_basic` 精确匹配，其次走 `fundsuggest` 搜索取第一个同类型结果，**必须用户确认**（重名基金是坑）。

### D.6.3 去重与幂等

```kotlin
// 指纹：同账户 + 同标的 + 同类型 + 同日期 + 同金额 + 同份额
fun fingerprint(t: TxnInput) = sha1(
    listOf(t.accountId, t.instrumentId, t.txnType, t.tradeDate,
           t.amount.money2(), t.shares?.shares4(), t.nav?.nav4())
        .joinToString("|")
)
```
- 导入前先做**预演（dry-run）**：显示"将新增 N 条 / 跳过重复 M 条 / 冲突 K 条"
- 冲突（同日同额但份额不同）→ 人工选择"保留新的/保留旧的/都保留"
- 同一文件重复导入 → 全部跳过（幂等）

### D.6.4 期初持仓建立（重要）

很多用户只想"从今天开始记"：允许建立**期初持仓**（`TRANSFER_IN`），字段为：份额、成本总额、起始日期。此后收益率与 TWR 从该日起算，并在 UI 明示"起点：2026-10-15（期初录入，此前收益未计入）"。**不允许伪造历史流水**来凑数据。

## D.7 归一化 / 去重 / 时区

| 问题 | 规则 |
|---|---|
| 净值日期 vs 交易日 | 一律以**净值归属日**（`nav_date`）落库；QDII 单独保留 `nav_actual_date` |
| 上金所夜盘 | `20:00–02:30` 归属**交易日期**（开盘日），跨自然日不拆分 |
| 时间戳 | 落库统一 UTC 毫秒；展示按用户时区（默认 Asia/Shanghai） |
| 行情快照去重 | 主键 `(instrument_id, ts)`，同 ts 覆盖（upsert） |
| 同日多源净值 | 优先级 `EM_F10 > EM_PINGZHONG > 缓存`，不一致时写 `audit_log` |
| 停牌/无成交 | `price = null`，不写 0；日线跳过该日（不补 0） |
| 分红除权 | 净值曲线断点用累计净值校验；若单位净值跳变 > 20% 且累计净值连续 → 判定分红，`nav_type` 标记 |

## D.8 健康检查与自愈

### D.8.1 每日探针（T15）

```
对每个关键接口：
  1. 发一次最小请求（固定样本标的）
  2. 校验：HTTP 200 / 非 HTML / 关键字段齐全 / 数值合理域
  3. 记录：成功率（7 日滚动）、延迟 P95、字段覆盖率
  4. 异常 → 自动降级到备源 + 写入诊断包 + 在「数据健康」页标红
```

### D.8.2 降级优先级（运行时）

```
主源（push2） ─失败→ 备源1（push2delay） ─失败→ 备源2（腾讯/新浪）
   ─失败→ 本地缓存（标记 STALE） ─失败→ UI 显示 `—` + 卡片级重试
```

### D.8.3 诊断包（用户可一键导出）

```
market_diagnostic_<ts>.zip
├─ manifest.json          # 版本/机型/系统/DB schema 版本/能力探测结果
├─ sync_log.jsonl         # 最近 7 天任务日志（脱敏）
├─ parser_failures.jsonl  # 解析失败样本（含原始响应片段，脱敏）
├─ field_coverage.json    # 各接口字段覆盖率
├─ capability_probe.json  # 灵动岛/闹钟/自启动探测结果
└─ README.txt             # 说明（不含持仓、不含金额、不含账号）
```
**纪律**：诊断包**默认不含**任何持仓、金额、账号信息；需要时由用户显式勾选"包含持仓结构（不含金额）"。

## D.9 缓存实现

### D.9.1 三级缓存

| 级 | 存储 | TTL | 用途 |
|---|---|---|---|
| L1 | 内存 LRU（`QuoteCache`，按 instrument） | 3~10s | 列表滚动、图表重绘 |
| L2 | Room `http_cache`（响应体） | 按 01 §6.3 表 | 冷启动秒开、离线可用 |
| L3 | Room 结构化表（`fund_nav`/`instrument_daily_bar`/…） | 永久 | 历史查询、回测 |

### D.9.2 Single-Flight（防重复请求）

```kotlin
class SingleFlight<K, V> {
    private val inFlight = ConcurrentHashMap<K, Deferred<V>>()
    suspend fun run(key: K, block: suspend () -> V): V =
        coroutineScope {
            val deferred = inFlight.computeIfAbsent(key) { async { block() } }
            try { deferred.await() } finally { inFlight.remove(key, deferred) }
        }
}
```
用于：同一 secid 被列表 + 详情 + 小组件同时请求时**只发一次**网络请求。

### D.9.3 stale-while-revalidate

```kotlin
fun observeQuote(id: Long): Flow<QuoteView> = flow {
    emit(cache.get(id)?.toView(stale = true))        // 立即给缓存（UI 秒出）
    emit(network.fetch(id).toView(stale = false))    // 再刷新
}.catch { /* 网络失败 → 保留缓存，标记 STALE */ }
```
**原则**：UI 永不"因为要刷新而空白"。
