# 附录 A：数据源与接口清单（实测版）

> 实测环境：2026-10-15，macOS curl，中国大陆出口
> 结论标记：✅ 实测可用　⚠️ 可用但有条件　❌ 实测失效　❓ 待验证（S0 探针任务）

## A.0 通用约定

**必需请求头**（缺失会被拒或被识别为爬虫）

```http
User-Agent: Mozilla/5.0 (Linux; Android 15; 23127PN0CC) AppleWebKit/537.36 Chrome/140.0 Mobile Safari/537.36
Referer: <对应站点>
```

**限流与反爬（实测经验）**

| 现象 | 触发条件 | 应对 |
|---|---|---|
| `push2*.eastmoney.com` 返回空 body | 同一出口短时间内 > ~20 次请求 | 请求合并（`secids` 批量）+ 退避 + 缓存；换 `push2delay` 主机 |
| `fund.eastmoney.com` 返回 404 HTML 页 | 部分旧接口已下线 | 适配器需容错，勿把 HTML 当 JSON 解析 |
| 新浪 `hq.sinajs.cn` | 无 Referer 直接 403 | 固定带 `Referer: https://finance.sina.com.cn/` |
| 返回编码 | 新浪为 **GBK** | OkHttp 需指定 charset，否则中文乱码 |

**多源降级矩阵**

| 语义 | 主源 | 备源 1 | 备源 2 | 终态 |
|---|---|---|---|---|
| A 股/板块/全球指数、个股行情 | `push2.eastmoney.com` | `push2delay.eastmoney.com` | 本地 K 线收盘价 | 标注「可能延迟」 |
| 分时 / K 线 | `push2his.eastmoney.com` | 本地缓存 | — | 标注「历史数据」 |
| 上金所 AU9999 | `www.sge.com.cn`（官方） | 东财 `118.AU9999` | 新浪 `gds_AUTD` | 缓存 |
| 国际金价 | 腾讯 `hf_XAU` | 新浪 `hf_XAU` | 东财 `118.AU9999` 反推 | 缓存 |
| 汇率 USDCNY | 新浪 `fx_susdcny` | 腾讯 `fx_susdcny` | — | 缓存 |
| 基金净值 | 天天基金 `lsjz` | `pingzhongdata` | 缓存 | 标注净值日期 |
| 浙商银行金价 | OCR/手动（用户） | 点差模型 | — | 标注来源 |

### A.1.1 ✅ 基金实时估值（官方）—— **已失效**

> **架构影响（重要）**：官方盘中估值已不可依赖 → 本产品的估值必须**自算**（见附录 B）。第三方估值仅可作为「校验源」，不得作为主路径，且必须处理其随时消失。

### A.1.2 ✅ 基金历史净值（分页，核心）

```
GET https://api.fund.eastmoney.com/f10/lsjz?fundCode=110011&pageIndex=1&pageSize=3
Referer: https://fundf10.eastmoney.com/
```

响应（实测）

```json
{"Data":{"LSJZList":[
 {"FSRQ":"2026-10-14","DWJZ":"4.0062","LJJZ":"5.7962","JZZZL":"0.04",
  "NAVTYPE":"1","SGZT":"限制大额申购","SHZT":"开放赎回","FHFCZ":"","FHFCBZ":""}
]}}
```

| 字段 | 含义 |
|---|---|
| `FSRQ` | 净值日期 |
| `DWJZ` | 单位净值 |
| `LJJZ` | 累计净值 |
| `JZZZL` | 日涨跌幅 % |
| `FHFCZ`/`FHFCBZ` | 分红/拆分金额、标志 |
| `SGZT`/`SHZT` | 申购状态 / 赎回状态 |

用途：长期净值库全量回填（20 年 ≈ 5000 行）、估值回测、收益计算。

以上字段映射适用于普通基金；货币基金的 `DWJZ` 和 `LJJZ` 按 A.1.3 解释为万份收益和累计万份收益，UI 与分析路由必须按基金类型区分。

### A.1.3 ✅ 货币基金收益历史

```
GET https://fundmobapi.eastmoney.com/FundMNewApi/FundMNHisNetList?FCODE=000198&pageIndex=1&pageSize=3&deviceid=WapDeviceId&plat=Android&product=EFund&version=6.2.8
→ {"Datas":[{"FSRQ":"2026-10-14","DWJZ":"0.2210","LJJZ":"0.8180","NAVTYPE":"1",...}]}
```

货币基金 `DWJZ` = **万份收益**（元/万份），`LJJZ` = 累计万份收益。它们复用接口字段和本地历史表，但不表示波动的单位净值；Android 端趋势、估算和基金自选按收益语义展示。

### A.7.1 Android 16 Live Updates（AOSP 标准，**推荐主路径**）

> ⚠️ 本次调研环境无法访问 `developer.android.com`（DNS 不可达），下表 API 名与最低版本**需在 S0 对照官方文档核对**（`Notification.ProgressStyle` 等为 API 36 新增）。

| API | 作用 |
|---|---|
| `Notification.ProgressStyle` | 进度/节点式实时样式：`setProgress()`、`setProgressPoints()`、`setProgressSegments()`、`setStyledByProgress()`、`setProgressTrackerIcon()`、`setProgressIndeterminate()` |
| `Notification.Builder#setStyle(ProgressStyle)` | 挂上实时样式 |
| `Notification.Builder#setRequestPromotedOngoing(true)` | 请求提升为"常驻实时更新" |
| `Notification.Builder#setShortCriticalText(String)` | 状态栏胶囊上的短文本（如 `−2.34%`）← **灵动岛胶囊文案的关键** |

### A.11.3 ❌ 浙商银行积存金仍无公开报价接口（但已不需要）

| 探测项 | 结果 |
|---|---|
| 官网 `/cn/personal/gold_3/`（财富金积存/财富金/代销实物贵金属） | 仅产品介绍，**无行情请求** |
| `ebank.czbank.com` / `h5.czbank.com` / `mbank.czbank.com` | DNS 不解析 |
| 手机银行 APK | `https://m.czbank.com/` → `CZBMobileBank_6_2_6.apk` |
| 上金所「上海金基准价」 | ✅ **公开**（见 A.11.1） |

**为什么没有公开接口（商业逻辑）**
1. 积存金是**银行自营产品**，报价 = 上海金基准价 + 银行自定买卖点差 → 属商业定价，公开等于暴露定价策略
2. 客户只在本行 App 交易，公开接口会**流失客户**且**增加被套利风险**
3. 银行无监管义务披露实时报价（仅需披露产品说明书与费率）

**那其他软件是怎么拿到的？分三类，都不是"随便拿"**

| 途径 | 代表 | 说明 |
|---|---|---|
| ① 银行自有渠道 | 浙商/工行/建行 App | 内部私有接口，需登录态 + 设备指纹，有风控 |
| ② **商业合作直连** | 微信「微黄金」（工行）、支付宝黄金 | **需与银行签约**，是 B2B 合作，非技术问题 |
| ③ **根本不是在报价银行金价** | 同花顺 / 东方财富 / 雪球 | 展示的是**上金所行情**（Au99.99 / Au(T+D) / 上海金基准价），不是银行报价 |
| ④ 爬虫 | 少数聚合站 | 有风控封禁与法律风险，不可持续性 |

> ⚠️ 特别注意：**支付宝「黄金」实际是代销黄金基金**（博时/华安黄金 ETF 联接），
> 不是银行积存金。这类产品用 T0 直连 AU9999 即可，实测 R² 99.5%。

### A.11.4 ✅ 因此的正确方案：不追银行接口，改为「基准价 + 标定点差」

```
浙商银行积存金买入价 ≈ SHAU_or_AU9999 × (1 + spread_buy)
浙商银行积存金卖出价 ≈ SHAU_or_AU9999 × (1 − spread_sell)

点差来源（按优先级）：
  1. 用户 OCR 截图（3~5 次真实样本即可标定）
  2. 用户手动输入报价
  3. 行业参考区间（0.3%~1%，仅作初始值，必须标注"模型折算"）
```

**已落库的数据源**：`SGE.SHAU`（上海金基准价）、`SGE.AU9999`（现货收盘）

### A.11.7 🔑 为什么银行不公开（商业逻辑，非技术问题）

1. **点差就是利润** —— 积存金买卖价差（通常 0.5~3 元/克）是银行贵金属业务的直接收入，公开报价 = 公开定价策略

3. **防套利** —— 公开实时双边报价会被人做跨行价差套利
4. **无监管义务** —— 监管只要求披露产品说明书与费率，不要求披露实时报价

> 工行的证据最能说明问题：**产品页说"每日公布挂牌价格"，但行情页跳转登录**。
> 这是**有意设计**，不是技术疏忽。

浙商银行积存金卖出价 ≈ SHAU × (1 − spread_sell)  ┘  spread 由 OCR 样本标定

| 点差来源 | 精度 | 成本 | 阶段 |

## A.13 国际金价 → 国内金价 → 银行积存金：误差传递实测

> 脚本：`tools/gold_chain.py`　样本：**2359 个交易日**（2016-12-19 ~ 2026-10-15）

### A.13.1 链路公式

```
折算金价(元/克) = XAU(USD/oz) × USDCNY ÷ 31.1034768
内外盘溢价     = 上金所Au99.99 − 折算金价
银行积存金      = 国内金价 ± 银行点差
```

### A.13.2 实测误差（① 折算精度）

| 指标 | 值 |
|---|---|
| 相关性 r | **0.999497** |
| **R²** | **99.8993%** |
| 平均溢价 | +1.782 元/克（+0.380%） |
| **MAE** | **4.783 元/克（1.021%）** |
| \|误差\| 分位数 | P50=2.98 / P90=10.84 / **P99=24.41** 元/克 |

### A.13.3 误差来源：内外盘溢价（② 稳定性）

| 年份 | 均值% | 标准差% | P5% | P95% |
|---|---|---|---|---|
| 2019 | +0.797 | 0.631 | −0.223 | +1.804 |
| **2020** | **−1.425** | **1.512** | −3.961 | +0.946 |
| 2021 | +0.384 | 0.716 | −0.692 | +1.668 |
| 2022 | +0.670 | 1.038 | −0.958 | +2.589 |
| 2023 | +1.491 | 1.282 | −0.324 | +3.526 |
| 2024 | +0.686 | 1.222 | −1.101 | +2.678 |
| 2025 | +0.067 | 1.029 | −1.516 | +1.801 |
| 2026 | +0.327 | 1.419 | −1.377 | +2.878 |

**溢价有强均值回归**：`ACF(1)=+0.417`、`ACF(5)=+0.364`、`ACF(20)=+0.300`
→ **可用滚动均值修正**：

| 修正方式 | MAE |
|---|---|
| 不修正 | 4.783 元/克 |
| 滚动 1 日溢价均值 | 4.349 |
| **滚动 5 日溢价均值** | **3.432（改善 28%）** |
| 滚动 20 日溢价均值 | 3.476 |

### A.13.4 方案对比（用哪个价推积存金）

| 方案 | MAE(元/克) | MAE(%) | 实时性 |
|---|---|---|---|
| **A. 上金所 Au99.99 + OCR 标定点差** | **≈0.5**（仅点差标定误差） | **0.11%** | 盘中可得 |
| B. 国际金价折算 + 5 日滚动溢价 + 标定点差 | 3.43 + 1.5 ≈ **4.93** | 1.11% | **24h 可得** |
| C. 国际金价折算（无溢价修正）+ 标定点差 | 4.78 + 1.5 ≈ 6.28 | 1.34% | 24h 可得 |
| D. 纽约金折算 | 5.044 | 1.076% | 夜盘可得 |
| E. **离岸人民币 USDCNH 折算** | **4.698**（最优国际方案） | 1.004% | 24h 可得 |

### A.13.5 结论

| 问题 | 答案 |
|---|---|
| 能否用国际金价推算国内金价？ | ✅ **能，R² 99.90%，MAE 1.02%** |
| 能否再推算银行积存金？ | ✅ 能，但**总误差 1.1~1.3%** |
| 这个精度够用吗？ | ⚠️ **银行积存金点差本身只有 0.5~3 元/克（0.06~0.34%）** → **推算误差（3.4~4.8 元/克）比点差还大，导致"推算出来的点差"毫无意义** |
| 那国际金价有什么用？ | ① **备用源**（上金所不可用时）② **非交易时段估值**（上金所日盘 15:30 收、夜盘 02:30 收 → 凌晨/周末有 6.5h+ 空档）③ **交叉校验**（溢价异常即预警） |
| **最优方案** | **主用上金所 Au99.99 / SHAU（公开免费）+ OCR 标定点差；国际金价仅作兜底** |

> ⚠️ **一个重要判断**：不要用国际金价去"推算"银行点差 —— 点差量级（0.5~3 元）
> 小于折算误差（3.4~4.8 元），推算出的点差是纯噪声。点差**只能靠 OCR 实测标定**。

### A.14.7 ✅ PCF 合成指数（存储关键）

**为什么要单独持久化**：原始 `pcf_component` 27 ETF × 80 成分 × 250 日 ≈ **22 MB/年**；
而合成指数 27 ETF × 250 日 ≈ **270 KB/年**（差 **80 倍**），且重算成本高（需成分股全量行情）。

→ **原始 PCF 只留 90 天，`pcf_synthetic_index` + `pcf_weight` 永久保留**。

```
pcf_synthetic_index(fund_code, trading_day, ret, n_used, n_total, weight_sum, cash_ratio)
pcf_weight(fund_code, trading_day, instrument_id, weight)
```

实测（2026-10-15，成分股行情已补全）：**合成指数 vs ETF 二级市场日线，平均 |差| 8.9bp、中位 6.9bp**
（差异来自 ETF 折溢价变动 + 现金替代部分，属正常范围）

### A.14.8 ⚠️ 工程坑：限流器持锁 sleep 会完全串行化

```python
# ❌ 错误：锁内 sleep —— 多线程吞吐等于单线程
with self._lock:
    gap = interval - (time.monotonic() - last)
    if gap > 0: time.sleep(gap)      # ← 持锁睡眠，其他线程全阻塞

# ✅ 正确：锁内只占坑，锁外睡眠
with self._lock:
    start = max(now, prev + interval)
    self._last[host] = start
    delay = start - now
if delay > 0: time.sleep(delay)
```

**实测影响**：修复前 493 只标的需 ~8 分钟；修复后并发 8 线程 **179 秒**（2.7 只/秒，已达新浪 0.35s 限流上限）。

### A.14.9 ⚠️ 熔断器误判：腾讯对非 A 股代码抛异常

批量采集中 `web.ifzq.gtimg.cn` 会被熔断（连续 4 次失败）——因为它对已退市/新股/非 A 股代码**抛异常**而非返回空。
**应对**：熔断后自动降级新浪（本次 493 只全部由新浪完成），属预期行为；
但应在熔断器上区分「**代码无效**」与「**主机故障**」（当前用 `bool(d)` 判定，对抛异常场景会误判）。
