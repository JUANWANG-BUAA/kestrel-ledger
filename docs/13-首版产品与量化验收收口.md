# 首版产品与量化验收收口

> 状态：准备阶段的开发基线，2026-10-15。适用于个人基金与黄金量化辅助软件的第一版。`docs/01`～`docs/12` 保留研究过程；范围或口径冲突时，以本文的首版决定为准。本文是规格，不表示 Android 功能已实现。

## 1. 产品目标与首版边界

用户完成一次持仓录入后，应能回答四个问题：现在持有什么、按已确认净值实际赚亏多少、盘中估值大致如何、近期收益和风险由什么驱动。基金和黄金均以人民币展示，同时保留原始币种、单位、报价时点及来源。量化结果用于辅助观察与复盘；界面不得把估算数字当作成交价或确定收益。

| 首版闭环 | 必须交付 | 暂缓到闭环稳定后 |
|---|---|---|
| 资产账本 | 手动录入账户、期初持仓、买卖、费用、现金分红；更正与撤销；每日快照 | OCR、CSV 多模板导入、跨设备同步 |
| 基金 | 历史净值、持仓真实收益、指数联接与主动股混代表样本的盘中估值及历史误差 | 全品类同时上线、复杂模型自动选择、全市场搜索 |
| 黄金 | 上金所 AU9999、黄金 ETF 的行情与持仓折算；银行积存金手动报价及报价时点 | 未经标定的银行买卖价自动推算、实时交易提示 |
| 总结 | 本地生成日、周、月事实报告，可追溯到快照和流水 | LLM 文案、自动投资建议 |
| 数据健康 | 关键源新鲜度、缺口、回填、估值降级状态 | 扩充所有全球市场数据源 |

首版研究样本选 2 只指数联接、3 只主动股混、1 只黄金 ETF、AU9999 和 1 个手动银行积存金账户。具体代码从现有数据覆盖与有效交易日筛选，固定在验收样本清单中；不能以“样本表现好”为由临时换样本。债券、QDII、货币和短债继续作为研究数据保留，进入产品时分别验收。

## 3. 统一数据契约

### 3.1 用户账本（不可重建，优先落地）

`account`：账户 ID、类型、币种、创建时间。`transaction`：稳定 ID、账户、标的、事件类型、申请时间、确认时间、状态、金额、份额、成交净值、费用、币种、来源、导入指纹、修订链。事件至少包括期初、买、卖、现金分红、红利再投、拆分、转入、转出和冲正。待确认交易不得改变已确认份额和已确认收益；更正以冲正及新流水保留审计轨迹。

`position_snapshot`：账户、标的、归属日、确认份额、成本、市值、估值状态、价格来源与价格时点。`portfolio_snapshot`：账户、归属日、持仓市值、现金、总资产、当日外部净流入、已确认收益、估算收益、数据完整度。唯一键为账户／标的／日期或账户／日期；重算必须幂等。期初持仓若没有原始交易史，明确标注“历史收益从录入日开始”，不得伪造更早的 XIRR。

### 3.2 市场事实与估值

每条行情或净值必须保留 `instrument_id`、`value`、`unit`、`currency`、`market_date`、`observed_at`、`source`、`quality`。区分净值归属日、发布时间和本机采集时间。黄金另存人民币每克的换算版本、汇率及汇率时点；银行报价分买入价与卖出价，手动输入或 OCR 标定均带有效期。

每次估值保留模型版本、输入版本、计算时间、估值归属日、估值变动、历史误差区间、质量等级及降级原因。无当前报价或无法确定汇率时展示“暂无可靠估值”，不沿用旧价形成当日收益。

### 3.3 数据保留和重算

流水、原始净值、每日组合快照与估值误差记录长期保留。公开数据可重采；用户账本必须加密备份。修正历史行情、分红或流水后，从最早受影响日重算快照与报告，并记录报告版本、输入指纹和生成时间。报表正文是派生结果，可以再生成。

## 4. 日、周、月报告的同一口径

所有周期使用同一个 `PeriodFacts(account, start, end, as_of)` 计算内核，再由模板写出文字。周期按 Asia/Shanghai 自然日、周一至周日、自然月划分；市场非交易日延用上一个**已确认**净值，但标明滞后天数。跨境标的保留当地市场日，不能把尚未收盘的海外报价标为国内当日已确认收益。

令 `V0`、`V1` 为含现金总资产，`F` 为周期内外部净流入（入金为正），则周期金额盈亏 `P = V1 - V0 - F`。账户内部买卖不是外部现金流。展示持有收益、已实现收益、分红、费用时要防止重复计入 `P`。TWR 按外部资金流切分子区间并连乘；XIRR 用逐笔外部资金流与期末资产算年化，现金流不足或多根无法判定时显示缺失及原因。短期报表以周期收益和金额盈亏为主，XIRR 只作附加指标并标注年化。

| 周期 | 必含事实 | 额外分析 | 缺数据时的处理 |
|---|---|---|---|
| 日报 | 资产、净流入、确认盈亏、盘中估算盈亏、各持仓贡献、黄金克价和报价时点 | 最大正负贡献、相对昨日配置变化 | 净值未发布则分列“已确认／估算”；关键价缺失则不计算合计估算 |
| 周报 | 期初期末、净投入、金额盈亏、TWR、基准收益、最大回撤、交易与费用 | 资产和基金贡献、集中度变化、估值误差 | 快照不完整则报告缺失日与缺失标的，隐藏不可计算指标 |
| 月报 | 周报全部字段、XIRR、累计与当月分红、资产配置、风险贡献 | 相对基准、行业／主题暴露、操作复盘与上月对比 | 期初持仓无完整历史时，仅计算录入后的区间指标 |

“贡献”优先按每日期初实际持仓权重乘实际收益累积，交易日内变动单独记录现金流和交易影响；不能直接拿月末权重乘整月收益。市场归因与“择时能力”只在有充分交易史和明确比较基准时展示，TWR 与 XIRR 的差额不能直接宣称为择时能力。

## 5. 量化验收与降级

首版模型先使用已验证的简单路由：指数联接对应指数；主动股混使用受约束回归并与报告持仓交叉检查；黄金 ETF 用实际交易价，AU9999 用官方报价；银行积存金仅显示用户输入或有效标定报价。研究中的 Hedge、弹性网与 PCF 主题因子可作为候选，先证明连续数据和样本外收益再进入默认路由。

| 门槛 | 验收定义 |
|---|---|
| 回放真实性 | 按发布时间截断输入；训练、调参、验收按时间顺序分开；预先冻结样本及对照基线；同一日期不能使用未来净值、持仓或 PCF |
| 样本量 | 每个默认展示估值的基金类型至少有 3 只代表基金、各不少于 120 个有效样本外交易日；首版样本不足的类型标为试验性并展示误差，不宣称类型级精度 |
| 误差 | 同一时点、同一有效日期比较模型与朴素基线的 MAE、中位绝对误差、P90 绝对误差、大波动日误差及方向命中；默认路由须在预先冻结的样本上 MAE 低于基线，且 P90 不恶化超过 10% |
| 区间 | 估值区间用训练期残差校准；样本外统计标称 90% 区间的实际覆盖率，低于 80% 或样本不足时不显示“置信”措辞 |
| 数据 | 应采与实采按标的×交易日核对；关键报价缺失、源时间戳异常或模型输入覆盖不足 80% 时停用当日数字估值，说明原因 |
| 稳定性 | PCF 连续 20 个交易日采集、合成、缺口回填与日志可追溯后，才作为首版默认模型的依赖；断源时可退回不依赖 PCF 的模型并标记降级 |
| 组合账本 | 同一流水重放两次得到同样份额、成本和快照；金额对账误差不超过 0.01 元；卖出、分红、拆分、撤销和跨周期入金均可重算 |
| 报告 | 日、周、月同一事实在不同报告中一致；每项结论可追溯数据、时点和计算版本；缺数不能静默填零 |

上述阈值是首版**进入默认展示的工程门槛**，不是预设模型已达标。对黄金银行价还需用至少 20 个跨不同时段的买入／卖出标定样本分别评估误差；未完成前只显示用户提供的报价，不给推算价。

## 7. Android 实现状态补记（2026-10-16）

第 2 节是 2026-10-15 的开发基线快照。其后 Android 已实现本地基金/黄金流水、持仓核算、每日组合观察快照，以及依据快照生成的日/周/月事实报告；当前收益率采用 Modified Dietz，并会在快照或报价不完整时隐藏不可计算指标。SQLite v8～v10 已加入现金事件、账户总资产、外部流时点估值与报价新鲜度；账户级 Modified Dietz、月度 XIRR 与 TWR 已接入。详细门槛仍以本文件第 4、5 节为准。

**实现进度补记（2026-10-16）**：SQLite v8 增加 `account_cash_events`；记账页支持建立期初现金并记录入金/出金，确认后的新买卖在现金已启用时同步更新余额。交易现金事件关联交易 ID，备份导入/导出包含现金事件；旧账本迁移不推测历史现金，现金跟踪起点由用户明确设置。SQLite v9 为 `portfolio_snapshots` 增加现金余额、账户总资产和当日外部净流入；v10 为外部资金流保存发生时间、流前总资产和估值完整度，并记录快照报价新鲜度。Domain 的 `AccountCashLedger` 区分余额变化与投资者外部现金流并校验非负余额；账户周期收益采用 Modified Dietz，月报增加按实际天数年化的 XIRR，TWR 在资金流时点以流前总资产分段连乘。历史资金流没有估值边界或周期边界报价过期时不展示账户收益率、XIRR 或 TWR，并给出原因；报价有效窗口为 72 小时，仍需留意数据源更新时间。

**后台快照补记（2026-10-16）**：App 启动时以唯一周期 WorkManager 任务安排每日 21:00（Asia/Shanghai）附近采集，允许系统在 1 小时弹性窗口内调度；前台打开和账本变化仍会及时更新当日快照。快照日是唯一键，同日重复采集覆盖同一条记录，避免重复计数。后台只用本机已有报价，不依赖网络；缺价会保留缺口，过期报价会将 `valuationFresh` 置为 false，不能进入要求新鲜边界的账户收益率计算。WorkManager 是尽力调度，省电策略可能延后运行；设备长期关机或强制停止应用造成的缺日不会用旧价回填。调度注册已在模拟器确认，连续每日执行与跨重启恢复仍需长期观察。

**配置与集中度补记（2026-10-16）**：纯 Kotlin `PortfolioAllocationAnalytics` 从期初/期末持仓快照和现金快照计算完整账户权重、HHI、有效资产数及百分点变化。计算前校验报价新鲜度、持仓数量/标识、持仓合计市值、现金与总资产；任一项缺失或无法在 0.01 元内对账则不返回配置值。日报只在昨日和今日都有快照时显示相较昨日的配置变化；周报显示 HHI、有效资产数及期初到期末权重变化；月报另列含现金的前五项配置。量化内核已有独立单测；`portfolio.period_report` 将配置事实按 PRIVATE_DETAIL 输出，UI 与 Agent 共用同一 `PeriodFacts`。这些是快照之间的账户配置变化，不代表资产归因或建议。

**期初持仓与资产首页补记（2026-10-16）**：记账页支持将基金或黄金现有份额及历史成本登记为已确认期初持仓，不生成虚构买入或现金流水；录入当期的周期收益、账户 TWR 和最大回撤不可用，之后以快照为起点。期初持仓纳入账本备份。首页已将账户资产与持仓置前；缺少报价时总资产显示不可用，避免将未知估值显示为零。Android 端通过 API 37 模拟器走通期初持仓、手动报价、持仓市值和含现金总资产核对；这验证了该输入路径，不代表 G2/G5 已整体验收。

**流水撤销补记（2026-10-16）**：记账成功后显示 5 秒撤销提示；`deleteTrade(id)` 在事务中删除该笔交易及关联现金事件，并重新校验持仓与现金账本，非法结果会回滚。API 37 模拟器验证了买入后及时撤销，持仓份额/成本恢复，现金及账本笔数返回撤销前状态。该能力只覆盖刚录入后的误操作撤销；历史更正仍需以冲正流水保留审计轨迹。

**交易流水与历史冲正补记（2026-10-16）**：资产页按日期倒序展示最近 5 笔交易，可展开查看全部；每行显示标的、类型、状态、金额、份额/克数、成交净值/克价和手续费。已确认流水可填写必填原因后冲正；原记录保留并标记冲正时间和原因，重算持仓并删除关联的派生现金事件。若剩余流水造成超额卖出或现金为负，事务回滚并拒绝冲正。冲正时将交易日期及之后已存组合快照标记为停用；App 随后按更正后的账本重建当前观察日，停用快照不参与分析。受影响外部资金流的流前估值也会清空，避免用陈旧边界计算 TWR。备份格式升级到 v2，导出快照有效状态，同时仍支持 v1 恢复。API 37 模拟器验证了一笔基金买入冲正：流水保留并显示原因，持仓归零、可用现金恢复至 ¥10,000，分析页仍显示 1 个有效观察日。超额卖出回滚和备份 v1/v2 恢复尚未在模拟器手工走查。
