# Market 全量优化计划

> 制定日期：2026-10-18。依据：`docs/17` 的三次审查（代码/后端、模拟器交互、UI 视觉）、`docs/14` 第二十四轮待办、`docs/13` 的首版验收口径。
>
> 执行原则：**用户价值优先、一次只做一个可验证的工作包、每个工作包都必须有测试 + commit + AVD 实机走查记录。** 没有模拟器证据的改动不标记完成。

## 1. 目标与非目标

### 1.1 总目标

把 Market 从“功能很多的原型”推进到“普通用户敢用、看得懂、愿意每天打开”的本机资产助手：

1. **不误导**：资产、收益、估值、提醒、报告的数字有来源、有日期、有缺失说明；不再出现“数据健康说全部有价格，报告说 0/1”的矛盾。
2. **不崩溃**：API 26–37 全版本可用；板块、基金、助手、备份、更新等路径不再有已知崩溃。
3. **不折腾**：已缓存的基金净值自动用于持仓；补价/更正后自动重算；用户不需要理解快照、基准、报价覆盖等内部概念。
4. **有辨识度**：从“蓝色金融模板”转为有主张的视觉系统；首屏、持仓、黄金三张关键页能让人记住“这是养基助手”。
5. **可信**：本机加密、数据不出设备、行情来源/时点、估算与真实净值的边界，都在界面上说清楚。

### 1.2 非目标

- 不做交易通道、不做投资建议、不承诺收益（产品红线不变）。
- 不做需要账号/云同步的强制能力；多设备只做可选的加密迁移。
- 不在本轮引入大型后端；仍以 Android 本地 + 公开数据源为主。
- 不为了“好看”牺牲可读性、性能或隐私。

## 2. 用户与任务

### 2.1 三个用户画像

**A. 小陈（基金定投，怕麻烦）**

- 只想知道：现在有多少钱、今天/本月赚亏多少、为什么。
- 最怕：手动抄净值、看不懂“快照覆盖 0/1”、更新后数据没了。
- 成功标准：安装后 2 分钟内完成“录入/导入 → 看到可信总资产与今日盈亏”。

**B. 老周（黄金 + 全球配置，重视数据）**

- 关心：国内金价、国际折算、溢价、来源时点；不接受把周五收盘价写成周日实时。
- 成功标准：每个数字都能点开看到来源、源时点、抓取时间；过期就明确说过期。

**C. 隐私敏感用户**

- 关心：持仓是否上传、加密是否真实、助手会不会把明细发给模型。
- 成功标准：首屏/设置能一眼看到“本机加密/默认不上传”；助手隐私开关与历史行为一致。

### 2.2 五个必须走通的任务

1. 新用户：录入一笔基金持仓 → 自动按最新净值估值 → 看到总资产与今日盈亏。
2. 老用户：补录历史买入 → 周/月报告、XIRR、回撤按新日期重算。
3. 黄金用户：打开黄金页 → 看到国内/国际/溢价，源时点真实，过期有标记。
4. 提醒用户：设置一条规则 → 前台/后台触发 → 通知可关闭、可解释。
5. 换机用户：导出加密备份 → 新设备恢复 → 账本、持仓、设置、助手数据都在。

## 3. 三次审查的合并结论

| 维度 | 主要问题 | 优化方向 |
|---|---|---|
| 后端/数据 | 快照 last-writer-wins、外部现金流不失效、基金净值不写回持仓、估值门槛缺失、提醒口径错误、HTTP 无上限 | 先修数据正确性与事务边界，再谈体验 |

### Phase 1：可信与不崩溃（约 2 周）

#### P1-01 Android 兼容与崩溃路径

- 修 `readNBytes`（API 26 手写读取）。
- 通知权限按 SDK 分支；低版本用 `areNotificationsEnabled`。
- 修 `AnimatedContent` lint error。
- 板块成分股“加自选”不再抛异常：不支持时隐藏入口 + 调用点兜底。
- 主线程写账本改为 IO；至少把新增的交易/现金写入移出主线程。
- **验收**：API 26/33/37 模拟器均能选文本附件、收到提醒；板块成分股不再崩溃；lint 0 error。
- **测试**：附件限长纯函数测试、通知权限决策纯函数测试、`MarketDetail` 不支持标的的 UI 逻辑测试；AVD 走查。

#### P1-02 账本历史日期与快照重算

- 所有 `add*` 接收 `day`；UI 日期选择器；禁止未来日期。
- 修正/补录后从最早受影响日重算快照；`savePortfolioSnapshot` 增加 observedAt CAS，避免旧写复活。
- 提供“重建观察点”入口（按当前账本从某日重算，幂等）。
- **验收**：补录上月买入后，本周/本月报告、XIRR、回撤可用；历史快照不再永久 0/1。
- **测试**：Ledger/日期/重算幂等；设备上补录一笔 10 天前买入并检查报告。

#### P1-03 基金估值闭环

- 场外基金按最近公布净值自动写入持仓估值；无净值时显示“净值日期”而不是“无报价”。
- 主指数路线补 `baseNav` 年龄门槛；T1 快照兜底同样补；训练窗口不早于披露日或使用历史持仓快照。
- QDII 改为交易日历对齐；T1 失败时保留 T2 兜底。
- 20 个验证点 → 至少 120 个样本外/3 只同类（按 docs/13）；未达标不显示 HIGH；补 P90/方向命中。
- **验收**：005827 无需手工补价即可看到市值；暂停净值/过期报告不显示数字；T1 失败有低质量参考。
- **测试**：估值门槛/前视/交易日历/回退；真实样本验收。

#### P1-03b 基金历史业绩

详见 [19-基金历史分析指标缺口](19-基金历史分析指标缺口.md)。

- 先补全量净值/复权口径、基准日线和数据完整性，再算指标；默认 120 个点不足以算 1/3/5 年。
- P0：区间收益、CAGR、最大/当前回撤、年化波动、基准超额、数据完整性。
- P1：夏普/索提诺/卡玛、下行波动、修复天数、滚动 1 年胜率、Beta/Alpha/跟踪误差/信息比率/捕获率。
- P2：费用/规模/经理/同类排名、历史持仓风格漂移、压力测试。
- **验收**：基金详情首屏 4 个结论（1Y 收益/年化/最大回撤/基准超额）；样本不足明确说明；基金净值口径与个人 XIRR/TWR 分开。
- **测试**：确定性净值序列的 CAGR/回撤/波动/夏普边界；<1 年不年化、<60 日不算夏普、无基准不显示超额。

#### P1-04 提醒正确性

- 缺报价不按 0 计入账户收益；纳入 realized；`QUOTE_STALE` 按最旧关键报价 + 源时点。
- `FUND_ESTIMATE_ABOVE` 接入估值结果或移除；通知“观测时间”有效期。
- 提醒 UI 增加权限状态/测试触发/后台说明；评估加原子 CAS，避免 UI 与 Worker 重复触发。
- **验收**：亏损提醒不会漏；过期提醒能按单标的触发；规则触发一次只有一条通知。

#### P1-05 数据一致性

- `addExternalCashMovement` 失效旧快照和后续资金流边界。
- 行情/快照/黄金日线写入按时间戳 CAS；刷新 single-flight。
- 卖出校验进事务；恢复备份期间暂停 Worker。
- **验收**：并发刷新不覆盖新报价；外部入金后 TWR/XIRR 边界重算；不会出现负持仓。

### Phase 4：逐页改造（约 2 周）

按“用户最常打开 + 最能建立信任”的顺序：

1. **总览**：一屏回答“有多少、今天怎样、钱在哪、下一步做什么”。
2. **持仓**：表格化 + 行内 sparkline + 自动估值 + 补价/更正入口。
3. **黄金**：金色成为主角；真实源时点；30 日变化与溢价分开标注；过期标记。
4. **自选**：市场分组、行内 sparkline、基金详情入口。
5. **记账**：日期优先、金额/份额/净值关系可视、保存前预览；空态引导。
6. **分析**：先结论后图表；报告/风险/基准分层；图表不吞滚动手势。
7. **板块**：热力/宽度带替代纯表格；统一色板。
8. **助手**：可见返回、模型名收进设置、空白态引导、隐私状态可见。
9. **外观/更新**：预览与真实组件一致；技术字段收进二级详情。

## 5. 工作包 Definition of Done

每个工作包完成必须同时满足：

1. **代码**：改动聚焦；不在同一 commit 混入无关重构；保持 120 列 Kotlin 目标。
2. **测试**：新增/更新对应单测或 instrumented test；关键数字有边界用例；不引入 0 覆盖的核心逻辑。
3. **构建**：`:app:assembleDebug` 通过。
4. **Lint**：`:app:lintDebug` 0 error；新增 warning 需说明。
5. **AVD**：安装新 APK，按 §7 脚本走查；至少 1 张 before/after 截图；记录 logcat 无 `FATAL EXCEPTION`。
6. **文档**：更新 `docs/14` 对应 ID 状态 + 证据；必要时更新 `docs/17/18`。
7. **Commit**：一个工作包一个 commit；提交信息遵循 `module: imperative summary`；提交前 `git diff --check`。
8. **回滚**：数据模型/迁移类改动必须有回滚或恢复路径；不在未验证时删除旧数据。

## 9. 量化验收

- 冷启动：P50 ≤2s，P90 ≤4s（当前约 4s，首次 27s）。
- 崩溃：五个任务 + 深浅色/横屏/旋转 0 crash。
- 数据：每个报告数字都有 source/date；缺失时显示原因；0 条“0/1”类工程文案。
- 估值：默认展示的基金类型满足 docs/13 的 3 只/120 日/P90；未达标只显示“试验性”。
- 视觉：每屏 ≤4 个字号；说明文字 ≥12sp；正文对比度 ≥4.5:1；圆角 ≤2 种。
- 交互：每个子页有可见返回；图表区域纵向滑动可滚页；旋转保留 tab/route/draft。
- 可访问性：TalkBack 能读出资产主数字、涨跌、按钮；不只靠颜色表达涨跌。

## 10. 风险与应对

| 风险 | 应对 |
|---|---|
| 数据模型改动导致旧库/备份不兼容 | 先写迁移 + 回滚测试；数据库版本递增；备份版本兼容；保留 recovery |
| 视觉改造范围过大 | 先 token + 三张关键页；确认后逐页；不在同一 commit 改全站 |
| 估值验收样本不足 | 先加门槛/降级，不用“好看数字”换验收；样本报告独立 |
| 模拟器网络不稳定 | 关键数据路径用本地 fixture；网络失败作为降级场景测试 |
| 主线程/性能回归 | 每阶段跑启动/滚动/记账耗时；数据库调用移 IO |
| 助手/隐私改动破坏可用性 | 先加测试和显式提示；保留离线模式；不默认上传明细 |
