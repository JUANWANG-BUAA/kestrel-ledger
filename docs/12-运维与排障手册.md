## J.2 十次实际事故（按发生顺序）

### J.2.1 事故①：K 线接口被持久封禁（push2his）

**症状**：`push2his.eastmoney.com` 连续返回 `RemoteDisconnected`，**冷却 45 秒后单次请求仍失败**；
采集脚本每个失败标的耗 25 秒（指数退避），51 个失败 = 20 分钟白等。

**根因**：`push2his` 存在**连接级持久限流**，触发后拉黑 IP 一段时间；而我的重试策略是 2s→4s→8s 指数退避，反而延长了痛苦。

**诊断**
```bash
# 单次请求测试（不看缓存）
python3 -c "
import sys; sys.path.insert(0,'tools')
from mkt.sources import tencent as tx
print(len(tx.kline_daily('1.600519')))"
# 若 push2his 相关全失败而腾讯/新浪正常 → 确认是该主机问题
```

**修复**
1. **K 线主源改为腾讯** `proxy.finance.qq.com/ifzqgtimg/appstock/app/fqkline/get`，新浪备源
2. 重试改为 **fail-fast**（≤2 次，0.6s/1.2s）
3. 加**主机熔断器**（连续 4 次失败 → 拉黑 900 秒）

**预防**：`push2his` 永久降级为第三源；`kline.py` 的 `BREAKER` 保持开启。

### J.2.2 事故②：熔断器误判（空结果被当成主机故障）

**症状**：批量采集时 `web.ifzq.gtimg.cn` 被熔断，之后**全部走新浪**（慢 3 倍）。

**根因**：腾讯对**非 A 股代码**（已退市、新股、部分 ETF）**抛异常或返回空**，
而熔断器用 `BREAKER.record(host, bool(d))` 判定 → 空结果被计为失败。

**诊断**
```bash
python3 -c "
import sys; sys.path.insert(0,'tools')
from mkt import kline
for s in ('1.600519','0.399001','1.159995'):
    d,src=kline.fetch(s); print(f'{s:12s} {len(d):5d} 条 源={src}')
print('熔断状态:', kline.BREAKER.states())"
```

**修复**：**空结果 ≠ 主机故障**，只有抛异常才计入熔断。
```python
d = tx.kline_daily(secid)
if d:
    BREAKER.record(_TX_HOST, True); return d, "tencent"
BREAKER.record(_TX_HOST, True)      # ← 空结果不罚
```
⚠️ 但仍有一个残留问题：腾讯对无效代码**抛异常**（不是返回空），所以熔断仍会误开。
**正确做法**：把「代码无效」与「主机故障」区分开（例如先查标的合法性）。

**预防**：熔断阈值不要设太小（当前 4 次）；批量任务按 host 分组跑。

### J.2.3 事故③：限流器持锁 sleep 导致完全串行化

**症状**：`fetch_quotes.py` 采 2150 只标的要跑 ~30 分钟；看起来像"卡死"。

**根因**：限流器在**锁内 sleep** —— 其他线程全部阻塞在锁上，多线程退化为单线程。

**诊断**
```bash
# 观察速率：正常应 ≈ 1/min_interval，若远低于则可能持锁
python3 tools/fetch_quotes.py --pcf-components -j 8 2>&1 | grep 速率
```

**修复**
```python
# ❌ 错误：锁内 sleep
with self._lock:
    gap = interval - (time.monotonic() - last)
    if gap > 0: time.sleep(gap)      # 持锁睡眠

# ✅ 正确：锁内只占坑，锁外睡眠
with self._lock:
    start = max(now, prev + interval)
    self._last[host] = start
    delay = start - now
if delay > 0: time.sleep(delay)
```

**效果**：493 只 **179 秒**（2.7 只/秒，已达新浪 0.35s 限流上限）。

**预防**：任何"限流器/令牌桶"实现，**sleep 必须在锁外**。

### J.2.4 事故④🔥：日期格式不匹配导致全表误删

**症状**：`archive.py --migrate` 输出 `pcf_component 过期 3022 行`（**全部删光**）。

**根因**：字符串比较 `"2026-10-15" < "20260717"` 为 **True**（`'-'` = 0x2D < `'0'` = 0x30）。
代码对 PCF 用 `%Y%m%d` 生成切割点，但库里存的是 ISO 格式。

**诊断**
```sql
-- 看实际格式
SELECT trading_day FROM pcf_component LIMIT 1;      -- "2026-10-15"
-- 验证比较行为
SELECT '2026-10-15' < '20260717';                    -- 1 (True!)  ← 就是它
```

**修复**
1. **格式自适应**：从样本推断（`"-" not in sample → %Y%m%d`）
2. **全删保护**：`if n == remain and n > 0: 拒绝执行`
3. 数据恢复：`collect_pcf.py` 是幂等的，重跑即可（PCF 当日仍在）

**预防**
- ⚠️ **归档脚本默认预演（dry-run）**，需显式确认才删除
- ⚠️ 任何 DELETE 前先 `SELECT COUNT(*)` 对比总行数
- ⚠️ 上线前先跑 `--dry-run` 验证

### J.2.5 事故⑤：`ts` 字段双重语义

**症状**：`archive.py` 对 `intraday30` 生成的切割点是 `1784291605`（Unix 秒），而实际存的是 `202607170000`。

**根因**：两张表都叫 `ts`，但 `instrument_quote_snapshot.ts` 是 Unix 秒，`intraday30.ts` 是 `yyyymmddhhmm`。

**诊断**
```sql
SELECT ts, LENGTH(ts) FROM intraday30 LIMIT 1;              -- 202610151500 (12位)
SELECT ts, LENGTH(ts) FROM instrument_quote_snapshot LIMIT 1; -- 1792051920 (10位)
```

**修复**：按样本长度自适应（≥12 位 → 日期串）。

**预防**：字段命名应带语义（`ts_epoch` / `ts_minute`），不要都用 `ts`。**已记入设计债**。

### J.2.7 事故⑦：前复权参数失效导致除权假跳空

**症状**：回测中银行股出现 −6.16% 的异常下跌，实际当天是分红除权。

**根因**：**腾讯 `fqkline` 的 `qfq` 参数实测未生效**（qfq ≡ raw，复权因子恒为 1.0000）。
→ 全部分析在用不复权价 → 除权日产生假跳空。

**诊断**
```python
# 对比 qfq 与 raw
import sys; sys.path.insert(0,'tools')
from mkt.http import HTTP
import json
for fq in (True, False):
    p = "sh600519,day,,,5,qfq" if fq else "sh600519,day,,,5,"
    txt = HTTP.get("https://proxy.finance.qq.com/ifzqgtimg/appstock/app/fqkline/get",
                   params={"param": p}, referer="https://gu.qq.com/", use_cache=False, retries=1)
    n = (json.loads(txt).get("data") or {}).get("sh600519") or {}
    arr = n.get("qfqday") or n.get("day") or []
    print(f"fq={fq}: {arr[-1] if arr else None}")
# 若两者相同 → 复权未生效
```

**修复**：`tools/adjust.py` + `stock_dividend` 表（1823 只 / 24,835 条）
```
真实收益 r = (P_t + cash_per_share) / P_{t−1} − 1       （含送转时再乘 (1+bonus+it)）
```

**归档原则**：存**不复权价（append-only）+ 分红表**，禁止存前复权价（每次分红都会改写全部历史）。

**实测影响**：除权日占 **0.401%** 观测，单点最大修正 6.23pp，**对平均 MAE 改善 ≈ 0%**
（是数据正确性修复，不是精度提升）。

## J.7 FAQ

**Q：PCF 能补历史吗？**
A：**不能**。上交所忽略所有日期参数，只返回当日。必须每日累积 → 所以定时任务越早挂越好。

**Q：为什么不用前复权价？**
A：前复权价会随每次分红**改写全部历史** → 训练集不可复现。正确做法是存**不复权价 + 分红表**。

**Q：短债为什么显示"不提供估算"？**
A：模型误差（0.87bp）大于信号（0.64bp）。给一个数字是**负价值**，也是误导。

**Q：国际金价能推算银行积存金吗？**
A：能，R² 99.90%，但 MAE 1.02%（3.4~4.8 元/克）**大于点差本身（0.5~3 元）** →
只能做兜底与非交易时段估值，**不能用来反推点差**。

**Q：为什么不上 CNN/LSTM？**
A：残差 ACF ≈ 0（白噪声）+ 与全部可观测特征相关 < 0.1 + 429 天样本 → 必然过拟合。
本轮又验证 4 个量化方法（卡尔曼/RLS/Huber/跨基金修正），实测收益 ≈ 0。

**Q：macOS 上 crontab 不执行？**
A：需要给 `cron` 授予「完全磁盘访问权限」（系统设置 → 隐私与安全性 → 完全磁盘访问）。

**Q：如何确认文档没漏东西？**
A：`python3 tools/doc_check.py` —— 检查引用有效性、表/工具文档化、陈旧数字、命名规范、交叉引用。
