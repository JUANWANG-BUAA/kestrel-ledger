# 发布与自更新（GitHub + CI）

> 目标：手机上装一次，之后应用内「关于与更新」检查 GitHub Release、下载并校验安装包，不丢账本。

## 1. 一次性准备：固定签名

自更新会比较 APK 签名证书；**每次构建签名不同，应用会拒绝安装**。所以必须用一把长期密钥，并让 CI 使用它。

```bash
keytool -genkeypair -v -keystore market-release.jks -alias market \
  -keyalg RSA -keysize 2048 -validity 10000
base64 -i market-release.jks | pbcopy   # macOS；Linux 用 base64 -w0
```

在 GitHub 仓库 Settings → Secrets and variables → Actions 添加：

| Secret | 内容 |
|---|---|
| `KEYSTORE_BASE64` | 上面 base64 的整段输出 |
| `KEYSTORE_PASSWORD` | keystore 密码 |
| `KEY_ALIAS` | `market` |
| `KEY_PASSWORD` | key 密码 |

> 这把密钥不要提交到仓库；丢了你以后无法覆盖安装，只能卸载（会清数据）。

## 2. CI/CD 行为

工作流：`.github/workflows/android.yml`

- push / PR：跑 `:domain:test`、`:data:testDebugUnitTest`、`:app:testDebugUnitTest`；
- 任意分支构建：产出 release APK + `.sha256`，上传为 artifact；
- 推送 tag `v0.2.1`：构建**签名 release APK**，创建 GitHub Release 并附 APK 与 `.sha256`；没有签名密钥时直接失败。

版本号由 tag 决定：`v0.2.1` → versionName `0.2.1`，versionCode `201`（major×10000 + minor×100 + patch），保证递增。

## 3. 第一次在手机上安装

1. 在 GitHub Releases 下载 `app-release.apk`；
2. 手机上允许「安装未知应用」；
3. 如果此前装的是 debug 包，签名不同，系统会要求卸载——**先导出加密备份**，再卸载安装；
4. 打开应用 → 抽屉 →「关于与更新」，把仓库改成你的 `owner/repo`，打开「启动时检查更新」。

## 4. 日常发版

```bash
git tag v0.2.1 && git push origin v0.2.1
```

CI 完成后，手机在下次启动或手动点「检查更新」时看到新版本；下载后会校验大小、SHA-256 与签名，通过才调起安装器。

## 5. 本地构建

- 无签名环境变量：`./gradlew :app:assembleRelease` 会用 debug 签名（只适合自测，不能用于自更新）；
- 有签名环境变量：设置 `MARKET_KEYSTORE`、`MARKET_KEYSTORE_PASSWORD`、`MARKET_KEY_ALIAS`、`MARKET_KEY_PASSWORD` 后构建；
- 版本可用 `VERSION_NAME` / `VERSION_CODE` 覆盖。

## 6. 常见问题

| 现象 | 原因 | 处理 |
|---|---|---|
| 更新页提示签名不一致 | 新包换了密钥 | 用同一把 keystore 重新构建；否则只能卸载重装（先备份） |
| 检查更新 404/403 | 仓库没有 Release，或 API 限流 | 确认 tag 与 Release 已发布；代理镜像只做下载加速 |
| 安装被系统拒绝 | 未授权「安装未知应用」 | 在系统设置为本应用开启 |
| 更新后数据不见 | 卸载重装导致数据目录被清 | 从加密备份恢复；不要用不同签名的包覆盖 |
