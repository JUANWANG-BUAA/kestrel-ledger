#### Android 端当前落地状态（2026-10-16）

当前 Gradle 模块为 `:app`、`:domain`、`:data`。`:domain` 使用 Kotlin/JVM，不依赖 Android SDK，承载组合收益分析、技术指标、板块历史风险计算，以及 `domain.assistant` 的 Agent/工具合同；`:data` 是 Android library，负责 SQLite 账本和公开行情接入。

模块化迁移仍在进行：行情网络解析和 SQLite 实现已离开 `:app`，Compose 页面仍集中在 `:app`，后续按 `data:source → data:repository → domain use case → feature` 的依赖方向继续拆分；新领域算法不得反向依赖 Android、Compose、SQLite 或网络 DTO。

行情仓储边界已覆盖报价和图表：`domain.market.MarketRepository` 提供缓存读取、报价刷新、OHLC 缓存读取和刷新；`ChartPeriod`、`MarketOhlcBar` 与 `CachedMarketChart` 是纯 Kotlin 领域模型。`:data` 中的 `MarketRepositoryImpl` 在 IO dispatcher 上协调行情源和 SQLite。首页黄金、板块、自选详情不再直接读写图表缓存或调用图表行情源。

组合量化内核新增 `XirrCalculator`：按实际天数/365 建模，合并同日现金流，以 Newton 求解、区间二分兜底，并在扫描范围内发现多根时返回不可用原因。对应 XIRR-01～05 已有 domain 单测。SQLite v8 增加账户现金流水；v9 快照增加现金、总资产和外部净流入；v10 记录外部资金流发生时间、流前账户估值和估值完整度，并标记快照报价新鲜度。现金跟踪由用户设定起点，旧流水不会被回放。账户周期 Modified Dietz 已使用总资产快照并扣除外部净流入；月报可用期初总资产、期间外部现金流及期末总资产计算年化 XIRR。TWR 使用外部现金流前的估值切分子区间并几何连乘；时间或估值缺失、边界报价过期时不返回结果。账户周期收益、XIRR 和 TWR 均要求周期边界报价不超过 72 小时，结果仍受底层公开报价更新时点影响。

`PortfolioRiskAnalytics.maximumDrawdown` 使用未舍入的逐日账户 TWR 构建资金流调整后的观察净值路径，再计算峰谷最大回撤幅度；只要基准日缺失、周期中任一自然日无快照、行情边界过期或流前估值不完整，就返回缺失日期/原因而不填造指标。回撤峰值日、谷值日与样本区间可供 UI 和 Agent 同时读取。该指标是本机已观察路径的历史最大回撤，不是预测风险；目前严格要求连续日快照，因此连续运行证据仍是必要条件。

`PortfolioAllocationAnalytics` 仅在期初、期末账户快照完整且新鲜，逐持仓行数和标识匹配，并且持仓市值、现金、账户总资产在 0.01 元内对账时输出全账户配置。现金作为单独配置项；权重以百分数展示，变化以百分点展示；HHI 为 0～1 的 `Σ(weight_fraction²)`，有效资产数为 `1 / HHI`。日报必须有连续昨日与今日快照，周/月比较各自边界快照；数据不足时只输出缺失原因。页面日报展示较昨日权重变化，周报展示集中度及边界变化，月报增加含现金的期末配置。`portfolio.period_report` 输出同源私密事实，仍受 Agent 隐私授权过滤。

Agent 合同只允许工具返回带来源与观测时间的事实，不提供交易或账本写入工具。`AgentToolRegistry` 按单轮 allowlist 分发工具、验证声明参数、限制事实数量，并拒绝缺少 key/value/source/observedAt 的事实；默认过滤 `PRIVATE_DETAIL`，共享私密持仓需要单独显式授权。`PrivacyGuardedAssistantAgent` 在 provider 边界再次执行默认过滤，只有请求包含显式共享同意时才保留私密事实。异常和畸形结果返回稳定错误码，不把实现异常文本交给模型。`:data` 的 `ReadOnlyAgentTools` 目前提供 `market.quote`（按名称或代码查询本地行情缓存、返回源时间与 72 小时新鲜标志；国际金价明确为原始 USD/troy oz）和 `portfolio.period_report`（复用领域日/周/月量化事实、输出保持私密）。行情工具不触发网络刷新；模糊搜索返回候选而不猜测。现金余额事实映射仍归为私密明细。本地规则摘要可不接入 LLM 独立运行。provider-neutral 合同与两个数据工具已有单测，但尚未连接聊天 UI 或外部模型。

每日资产快照由 `:app` 的 WorkManager Worker 调度，通过 `domain.portfolio.PortfolioSnapshotRepository` 访问 `:data` 本地实现；后台 Worker 不读取 Compose 状态，也不触发行情网络请求。唯一周期任务使用 `KEEP`，目标为上海时间每日 21:00、1 小时弹性窗口；WorkManager 允许系统延迟，不能据此承诺精确时刻或补齐设备关机期间的历史报价。

**禁止事项（Detekt 自定义规则 + PR 检查）**

| 禁止 | 原因 |
|---|---|
| `domain` 依赖 Android SDK / Room / Retrofit | 保证算法可在 JVM 单测与回测中跑 |
| `feature` 之间互相依赖 | 防止耦合；共享逻辑下沉到 `domain`/`designsystem` |
| `data:source/*` 之间互相依赖 | 多源必须独立，由 repository 编排 |
| `domain` 中出现 `String` 拼接的日期/货币运算 | 统一用 `java.time` / `BigDecimal` |
| 直接 `GlobalScope` / `runBlocking`（除测试） | 结构化并发纪律 |
| 在 `data` 层暴露 DTO 给上层 | 必须映射为领域模型 |
| `Float`/`Double` 参与金额计算 | 金额一律 `BigDecimal`（价格可用 Double 但落库前转） |
| 硬编码时区偏移（`+8`） | 必须 `ZoneId` |
| 硬编码数据源 URL 到 `feature`/`domain` | 只能在 `source` 层 |

### E.1.3 协程与线程规范

```kotlin
// Dispatcher 必须注入，禁止硬编码 Dispatchers.IO（便于测试替换）
class ComputeEstimateUseCase @Inject constructor(
    @IoDispatcher private val io: CoroutineDispatcher,
)
```
- 写库：`Dispatchers.IO` + Room 事务
- 重计算（回归、回测）：`Dispatchers.Default`
- UI：`viewModelScope` + `StateFlow`（`stateIn(WhileSubscribed(5_000))`）
- 长时间后台：WorkManager（可被系统调度），**不用**自建线程池
- 盯盘前台服务：`LifecycleService` + 结构化并发

### E.1.4 静态检查

| 工具 | 规则要点 |
|---|---|
| ktlint | 官方格式，`max_line_length = 120` |
| detekt | 复杂度阈值（函数 ≤ 40 行 / 圈复杂度 ≤ 12）、禁止上述清单、`TooManyFunctions` 白名单给 UiState |
| Android Lint | 忽略不得滥用；`NewApi` 必须走 `@RequiresApi` 或能力探测 |
| 编译告警 | `allWarningsAsErrors = true`（除依赖库告警） |

## E.2 构建与 CI/CD

### E.2.1 构建变体

| 变体 | 用途 | 差异 |
|---|---|---|
| `debug` | 开发 | 允许明文 DB、Mock 数据源开关、日志全开 |
| `staging` | 内测 | 真实数据源 + 崩溃收集 + 计时统计 |
| `release` | 发布 | R8 全开、SQLCipher、Baseline Profile、日志脱敏 |

**依赖注入开关**（便于离线开发与演示）：`DataSourceMode = REAL | MOCK | REPLAY`。`REPLAY` 模式用 `fixtures/` 回放网络响应，**无网也能跑完整 UI 回归**。

### E.2.2 CI 流水线

```
push / PR
 ├─ 1. lint + detekt + ktlint          （< 2 min）
 ├─ 2. 单元测试（JVM）                  （< 4 min）
 │     ├─ domain（成本/XIRR/TWR/估值/提醒/日历）
 │     └─ data（解析器契约测试）
 ├─ 3. 覆盖率门禁                       （domain ≥ 85%，data ≥ 70%，整体 ≥ 60%）
 ├─ 4. 构建 debug + staging            （< 5 min）
 ├─ 5. Robolectric 关键流程             （< 4 min）
 └─ 6. 回测任务（夜间）：估值引擎历史回放 → 产出 MAE/命中率报告（失败则阻断发布）

release 分支
 ├─ 7. Baseline Profile 生成 + Macrobenchmark 性能门禁
 ├─ 8. 兼容性冒烟（真机 / 云真机矩阵）
 └─ 9. 签名 + 输出 AAB/APK + 版本说明
```

### E.2.3 版本与签名

- `versionName = major.minor.patch`（语义化）；`versionCode` 单调递增
- 签名用 Gradle `signingConfigs` + 本地 keystore（**不入库**），CI 用加密环境变量还原
- 每个 release 附「数据源兼容性说明」（本次适配了哪些接口变更）→ 便于回滚决策

## E.3 数据库迁移

| 规则 | 说明 |
|---|---|
| 版本单调 | Room `version` 只增不减；每次改动必须提供迁移 |
| 优先 auto-migration | 加列/加表/加索引用 `@AutoMigration` |
| 手工迁移 | 涉及数据转换（如成本口径变更）必须写 `Migration` + **迁移测试** |
| 迁移测试 | `MigrationTestHelper`：从 v1 逐版升到 vN，断言行数与关键字段 |
| 大表迁移 | `fund_nav` / `quote_snapshot` 迁移用分批 + 事务，避免 ANR；必要时用「复制新表 + 重命名」策略 |
| 失败兜底 | 迁移失败 → 不静默重建！先导出原始 DB 到 `files/recovery/`，再提示用户（可上传诊断包，不含金额） |
| 降级 | **不支持降级**（DB schema 不向后兼容）；安装旧版 APK 会检测到更高版本并只读打开，提示恢复备份 |
| 迁移前自动备份 | 任何 schema 变更前自动做一次本地加密备份（保留 3 份） |

**字段级兼容纪律**
- 新增字段必须可空或有默认值
- 删除字段先「停止读写」→ 隔一个版本再删（两阶段删除）
- 语义变更（如 `avgCost` 从「不含费」改「含费」）必须写进迁移脚本 + `audit_log` + 版本说明

### E.4.7 用例清单 · 解析器契约（每个解析器 4 条）

| 模板用例 | 说明 |
|---|---|

## E.5 质量门禁与发布

| 门禁 | 阈值 | 不通过后果 |
|---|---|---|
| 崩溃率 | < 0.3%（日活） | 阻断放量 |
| ANR 率 | < 0.2% | 阻断放量 |
| domain 覆盖率 | ≥ 85% | 阻断合并 |
| 回测 MAE（股混） | ≤ 0.35% | 阻断发布（估值是核心卖点） |
| 提醒误报率（回放） | ≤ 10% | 阻断发布 |
| 性能回归 | 任一指标劣化 > 15% | 阻断发布 |
| 解析器契约 | 全绿 | 阻断发布 |

**灰度与应急**

```
内测(自己+3人) → 10% → 50% → 100%
每档观察 24h：崩溃率 / 解析失败率 / 接口成功率
```

**接口失效应急预案（最高频风险）**

| 事态 | 动作 | 时效 |
|---|---|---|
| 单接口字段变化 | 解析器容错兜底 → 该卡片降级 → 写诊断包 | 立即 |
| 单接口完全失效 | 自动切备源；「数据健康」标红 | 立即 |
| 主源域名变更/封禁 | 服务端配置热更新的**源地址表**（本地默认值 + 可选远端覆盖） | ≤ 1 天 |
| 全面失效 | 内置「数据源自检」页 → 用户可看到哪些数据不可用 + 本地历史数据仍完整可用 | 长期 |
| 紧急修复 | 走 hotfix 分支，仅改解析器；**不动 DB schema** | ≤ 48h |

> 设计前提：**数据源随时可能失效**。产品必须做到"源挂了，账本依然完整可用"——账本是最强护城河，行情只是附加价值。

## E.7 安全威胁模型（STRIDE）

| 威胁 | 场景 | 对策 |
|---|---|---|
| **S**poofing | 他人拿到未锁屏手机查看资产 | 生物识别应用锁（可选）、金额隐藏模式、`FLAG_SECURE` 防截屏（默认关，用户可开） |
| **T**ampering | Root 设备读取/篡改 DB | SQLCipher + Keystore 密钥；检测 root 仅提示（不阻止，避免误伤） |
| **R**epudiation | 用户误改数据无法追溯 | `audit_log` 记录增删改前后值；流水软删除 |
| **I**nformation disclosure | 备份文件泄露 | 备份加密（口令派生 Argon2id → AES-GCM）；导出文件含校验与免责声明；诊断包默认脱敏 |
| **D**enial of service | 大量数据导致卡顿/OOM | 分页 + 降采样 + 定时清理；大表查询加索引；列表用 Paging |
| **E**levation | 第三方 SDK 窃取数据 | 无第三方 SDK（除 ML Kit）；网络层域名白名单；`network_security_config` 仅允许 HTTPS + 已知域名 |
| 中间人 | 公共 WiFi 劫持行情/净值 | 强制 HTTPS + 证书固定（对关键域名 pinning，含备用 pin） |
| 恶意截图/OCR 注入 | 伪造持仓截图导致错误数据 | OCR 必须人工确认；一致性校验；批次可撤销 |
| 权限滥用 | 申请无关权限 | 权限清单最小化（见 `01` §7.4），首启不批量索权 |

**数据分级**

| 级别 | 数据 | 存储要求 |
|---|---|---|
| L1 公开 | 行情、净值、公开季报 | 无特殊要求（可缓存明文） |
| L2 敏感 | 持仓、流水、成本、金额 | SQLCipher 加密库；诊断包/日志脱敏 |
| L3 机密 | 备份文件、导出文件 | 口令加密（Argon2id + AES-GCM），口令不落盘 |

## E.8 备份 / 恢复 / 换机迁移

| 场景 | 方案 |
|---|---|
| 日常自动备份 | 每日 04:00 生成加密备份（保留 7 份，本地私有目录） |
| 手动导出 | 生成加密包（口令由用户设置，强度校验 ≥ 8 位含字母数字）→ SAF 保存到用户选择位置/网盘 |
| 恢复 | 选文件 → 输口令 → 校验完整性（SHA-256）→ 预览"将导入 N 条流水 / M 只持仓" → 确认 |
| 换机 | 同上（推荐"全量导出 → 新机导入"） |
| 多设备（P2） | 端到端加密同步（服务端只存密文，密钥由口令派生）；冲突用"流水并集 + 按 txnId 去重" |
| 迁移校验 | 恢复后自动跑一致性自检（`03` §B.9），失败则提示并保留恢复前快照 |

**备份内容清单**

```
backup_<ts>.mkt (zip, AES-GCM)
├─ db.sqlite.enc        # 主库（SQLCipher 导出的明文再加密，避免双重密钥耦合）
├─ settings.json        # 用户设置（含提醒规则、主题、涨跌色）
├─ ocr_templates.json   # 自定义模板（若有）
├─ manifest.json        # 版本、schema 版本、条数、SHA-256、生成时间
└─ README.txt           # 恢复说明 + 免责声明
```
